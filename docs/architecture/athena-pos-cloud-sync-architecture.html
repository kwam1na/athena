Architecture · POS · Local-first Sync

Athena keeps the register local and the business state shared

Two views separate the system boundary from the terminal mechanics. Start with the cloud-sync overview; use the second diagram to see exactly how a cashier action becomes a durable local event and later converges with Athena Cloud.

01 · System overview

POS executes locally, then converges through one ordered sync boundary

The register does not wait on Convex to complete a cashier command. The cloud accepts terminal events in sequence, projects canonical records, and returns reconciliation evidence to the same durable local state the UI reads.

Immediate authority: the terminal is authoritative for whether a cashier command was durably recorded. A healthy local store can keep selling without the network.

Shared authority: Athena Cloud becomes canonical after ordered admission and policy-aware projection. Completed local history is preserved when reconciliation is needed.

Not pictured: catalog transport, provisioning, and diagnostics are supporting lanes, not part of the sale-to-cloud authority path.

02 · POS mechanics

Inside the terminal, every cashier decision returns to one durable local projection

The command gateway validates against local policy inputs, appends the event before reporting success, and refreshes the read model. Outbound upload and inbound register authority remain separate background lanes.

Cashier contract: a command succeeds only after non-reconstructable facts survive reload. The UI then renders the refreshed local projection rather than waiting for cloud confirmation.

Outbound lane: the scheduler drains stable ordered pages, retries safely, and writes returned mappings and outcomes back to IndexedDB.

Inbound lane: lifecycle authority applies independently of upload and heartbeat; it informs the next local command but never invents a financial event.

Primary implementation boundaries: localCommandGateway.ts, posLocalStore.ts, syncScheduler.ts, usePosLocalSyncRuntime.ts, and useRegisterLifecycleAuthorityRuntime.ts.

Cloud boundary: public/sync.ts, ingestLocalEvents.ts, projectLocalEvents.ts, and public/terminals.ts.

Contract: shared/posLocalSyncContract.ts.
