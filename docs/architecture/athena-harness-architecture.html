How Athena turns a change request into reusable proof

The agent uses repo-local guidance to prepare an exact candidate. pr:athena then orchestrates two distinct gates—contract preflight and obligation admission—before validation, evidence recording, and pull-request CI.

Ownership boundary: the Delivery Orchestrator sequences the gates; it does not implement their policies. Contract Preflight detects static harness drift. Obligation Admission decides whether the exact candidate may enter merge-grade validation.

Successful path: candidate → orchestrator → preflight → admission → providers → evidence. GitHub CI independently re-runs the harness contracts. Sources: harness-app-registry.ts, harness-gate-registry.ts, and pr-athena-delivery-run.ts.
