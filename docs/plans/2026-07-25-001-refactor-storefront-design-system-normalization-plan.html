Normalize the storefront design system

Turn the storefront's existing Tailwind, Radix, shadcn-style, CVA, and Framer Motion foundations into an authoritative customer-facing system without copying Athena's operator visual language or changing commerce behavior.

Problem frame

Storefront has the ingredients of a design system but no governing authority. Feature code bypasses partial tokens and a large primitive inventory with raw palette utilities, arbitrary dimensions, duplicated forms/modals, route-local spacing, and one-off motion.

57 UI files

A sizable primitive inventory, but no supported/experimental/deprecated catalog.

44 container repetitions

The implicit 1024px layout has no named component or token authority.

247 arbitrary values

Responsive and sizing decisions are scattered through features.

59 blank-state candidates

Critical routes often render null or an empty viewport while loading.

33 shared filenames

Only 12 Athena/storefront primitive filenames remain byte-identical.

Zero storefront stories

No living workbench currently documents foundations, patterns, or templates.

Safety leads the roadmap. Pinch zoom is disabled and the central controls commonly suppress browser outlines without providing a reliable visible focus treatment. These are foundation defects, not route-level polish.

Target system

Reuse Athena's system shape, not its visual identity. The storefront remains customer-facing, comfortable, image-led, and brand-specific.

Customer doctrine
Semantic foundations
Accessible primitives
Commerce patterns
Journey templates
Automated enforcement
Visual thesis: warm, image-led, refined commerce with quiet neutral surfaces, one recognizable action accent, comfortable touch density, and typography that supports merchandise instead of competing with it.

Key decisions

DecisionWhy
Normalize components/ui in place.A directory move creates import churn but does not improve contracts.
Keep semantic values storefront-local.Customer commerce and operator workflows need different hierarchy, density, shell, and brand values.
Light-first, theme-ready.The current dark block is incomplete and has no application authority.
Use temporary accent aliases.Route-by-route migration is safer than a flag day.
Primitives do not own commerce state.Foundations cannot import product, route, analytics, or checkout behavior.
One active Storybook config.Avoid Athena's current duplicate-config drift and ensure a11y runs in the real workbench.
Freeze nonvisual contracts first.All 34 route sources must trace selectors, telemetry, URLs, state, persistence, and synthetic/redacted baseline evidence.
Checkout storage remains immutable unless versioned.Field normalization must not strand persisted customer sessions.
Preserve current auth return paths.Changing destinations is product behavior outside this refactor.
Use WCAG 2.2 AA as the normative baseline.Accessibility cannot depend solely on local conventions that the audit already found deficient.
Use synthetic/redacted review artifacts.Storybook, screenshots, and traces must not become a customer-data, token, or payment-data exposure channel.
No shared package yet.Extract only after real usage proves identical neutral contracts.

Implementation units

U1

Contract freeze, foundations, and accessibility

Trace every route's states, selectors, telemetry, persistence, and synthetic/redacted evidence. Establish doctrine, WCAG 2.2 AA mapping, semantic tokens, light-first authority, zoom, focus, and reduced-motion contracts.

Primary outputs: design guide, 34-route migration baseline, artifact policy, token/config tests, canonical CSS/Tailwind/viewport wiring.

U2

Workbench and guardrails

Create one active Storybook workbench with Guidance, Foundations, Primitives, Patterns, and Templates; enable a11y and add an executable changed-file raw-value policy.

Guardrails land early so migration does not accumulate new drift.

U3

Action and form primitives

Harden button hierarchy, 44×44px standalone touch targets, loading, icon actions, inputs, selection controls, labels, help, and validation semantics.

Exit evidence: keyboard, names, focus, native disabled/busy, stable loading dimensions, form associations, consumer inventory, and unmigrated-journey compatibility smoke tests.

U4

Overlay, state, feedback, and media patterns

Normalize dialog/sheet focus, state-content and overlay behavior matrices, async states, safe errors, status roles, skeletons, and image fallback/aspect/alt behavior.

Terminal states retain distinct domain meaning, and every overlay records dismissal, focus, scroll, and teardown behavior.

U5

Shell and responsive layout migration

Encode page/container/section/grid rhythm and migrate every live shell mutation to a declarative model for homepage, browsing, checkout, receipt, banner, menus, bag, filters, and scroll visibility.

Overlay teardown must restore body scroll, focus, navbar state, and route-correct composition.

U6

Catalog and product migration

Migrate homepage, filters, cards, gallery, variants, reviews, inventory/offer states, and mobile actions as the first complete commerce template; relocate merchandising-aware modals out of the primitive boundary.

Mobile and desktop share state/action components, and a fit review must explicitly revise or approve the system before checkout.

U7

Bag and checkout migration

Converge duplicated fields and normalize conversion surfaces while preserving schemas, storage, fulfillment, fee logic, payment branches, terminal semantics, retries, telemetry, authorization boundaries, and idempotency.

Checkout lands only after primitives and catalog have proven the system.

U8

Account, post-purchase, and content routes

Migrate account, orders, rewards, saved items, reviews, policies, contact, receipt, maintenance, and not-found independently of checkout; relocate review-aware modals to their feature boundary.

Current post-auth destinations, protected-data boundaries, and partial guest-ownership transfer behavior remain unchanged.

U9

Final catalog cleanup

Classify the supported UI catalog and remove only zero-consumer aliases, copies, assets, native-control bypasses, and policy exceptions after U6, U7, and U8 complete.

Supported components/ui files may not import route, API, query, telemetry, or feature state; cleanup remains a separate rollback boundary.

Risks and mitigations

Accidental redesign

Lock semantic roles and visual thesis; migrate behavior-preservingly with route snapshots.

Flag-day token rename

Use temporary aliases and enforce semantic roles on new/changed code first.

Primitive blast radius

Add contract tests, preserve compatibility variants, and migrate by journey.

Checkout regression

Characterize persistence and state first; require compatibility gates and idempotent refresh/retry.

Static-only accessibility

Require keyboard, focus restoration, live regions, reduced motion, contrast, and zoom evidence.

Storybook drift

Use app foundations and one active configuration protected by tests.

Athena coupling

Reuse governance only; keep operator tokens, shell, density, and page treatments separate.

Unsafe cleanup

Delete only after import evidence, snapshots, route migration, and zero live usage.

Verification strategy

  • Keyboard-only traversal across navigation, filters, product/gallery, bag, checkout, overlays, auth, and post-purchase.
  • WCAG 2.2 AA mapping plus visible focus, accessible names, focus restoration, live async feedback, and native disabled/busy behavior.
  • Reduced-motion runs with no delayed hidden navigation, infinite demand pulse, or staged essential content.
  • Named responsive widths: 320, 375/390, 767/768, 1024, 1279/1280, and wide desktop, plus landscape/zoom/large text.
  • State matrices for loading, background refresh, empty, recoverable error, terminal error, disabled/pending, and success.
  • Checkout persistence, fulfillment transitions, payment branches, terminal direct-entry/refresh/retry, and mutation idempotency.
  • Token/config policy, primitive consumer compatibility, Storybook a11y/interaction checks, browser snapshots, package build, and mapped harness behaviors.
  • Protected-route negative tests and preservation of route/search contracts, readiness selectors, test IDs, telemetry, observability, API, and domain outcomes.
  • Synthetic fixtures and redacted artifacts with documented access, deployment, retention, and secret/token prohibitions.
Success means authority, not merely consistency. Routes should consume a documented and tested vocabulary; contributors should be prevented from introducing new visual and accessibility drift while the old inventory is deliberately retired.
