Outcome and boundary

The consuming gate evaluates typed obligations after a wrapper-owned preparation sequence and immediately before expensive work. Review is historical, provider-issued, and exact-candidate-bound; documentation currentness is computed live. Humans may deliberately waive review for one invocation, agents may not, CI must match repository-authorized policy, and unknown contexts block.

One cost boundary. pr:athena and pr:athena:validate delegate immediately to a guarded pr:athena:validate-provider. The long-lived wrapper requires a current preparation receipt and directly spawns wrapper-owned command metadata, preventing direct-child and post-admission shell bypasses.

V1 does not migrate all gates, guard raw internal commands, create a workflow scheduler, use tracked markers, add cryptographic identity, or change documentation policy.

Admission model

1. Verify preparation receipt; capture tree, base tip, merge base, context
2. Activate obligations and evaluate all facts
3. Resolve evidence, delegation, or human waiver
4. Recheck identity, record decision, directly spawn provider

Review activates at 50 relevant added-plus-deleted lines, inclusive, or when an existing validation scenario with an explicit required reviewSensitive: true is touched. Freshness binds the complete prepared tree and current base tip; activation and reviewer scope use the merge base so upstream-only changes are not attributed to the candidate.

Evidence-bearing lifecycle: prepare → independent review → if fixed, prepare again → complete re-review → finalize provider manifest → exact-match and store evidence → admission → heavy validation → later merge-ready review.

Implementation units

U1 · Preparation, candidate, and surfaces

Create a wrapper-owned preparation receipt, stable tree/base-tip/merge-base capture, activation classification, and explicit scenario IDs/sensitivity.

Characterization-first: preserve existing pre-push proof and generated-map behavior.

U2 · Registry and evaluator

Define gate/obligation/provider policy and a pure aggregate evaluator with disjoint tagged outcomes.

Test-first: decision table before adapters.

U3 · Context and records

Centralize CI/agent/human/unknown precedence and atomic Git-private evidence/waiver persistence.

U4 · Review adapters

Let ce-code-review and the new pre-validation execute checkpoint finalize provider-owned manifests only after green review of the final prepared candidate.

U5 · Documentation provider

Expose structured live documentation facts while preserving the public CLI and evaluating policy once.

U6 · Athena admission

Guard and directly spawn the heavy provider, aggregate blockers, use invocation-scoped human waivers, recheck identity, and emit correlated telemetry once.

U7 · Audit and guidance

Detect dangling IDs and bypass wiring, extend proof fingerprints, update canonical docs, regenerate maps, and rebuild Graphify.

Verification strategy

  • Qualifying agent calls through every public Athena path start zero heavy commands without fresh evidence.
  • Exactly 49 relevant lines do not activate; exactly 50 do; relevant binary changes and sensitive one-line edits activate.
  • Any full-tree or base-tip change stales evidence and reusable waivers; merge-base scope excludes upstream-only changes.
  • Agent plus TTY never receives a human prompt; undeclared CI and unknown noninteractive contexts fail closed.
  • Both approved providers produce interchangeable evidence only from complete final manifests; every review mutation triggers preparation and a full re-review.
  • Documentation failures aggregate, block every actor, keep standalone CLI compatibility, and run once per admission.
  • Prompt-time drift leaves no reusable waiver; final capture closes the admission race; direct and outer telemetry are correlated to one invocation.
  • Self-audit rejects missing wrappers, aliases that work before admission, dangling IDs, and incomplete proof fingerprints.
