Summary

Wire the existing independent reporting verifier (packages/athena-webapp/convex/reports/verify.ts) into the automation stack: a cron-driven per-store sweep verifying settled day folds and the current week against source domains, durable run/outcome recording (new verification-run table + scheduled-run ledger), and a new email notification kind that fires only on unexplained discrepancies. Email is gated off at launch (record-only rollout).

The verifier is a 2,000-line second opinion that has already caught two real defects invisible to a green test suite — but nothing triggers it today, and its unverifiedFields output has no consumer. This plan is that consumer.

Scope

Requirements (abridged)

  • R1 Scheduled per-store day + week verification, no operator involvement
  • R2 Every run recorded durably — including clean runs, errors, skips
  • R3 New notification kind emails on unexplained discrepancy; clean runs silent
  • R4 “Checked and wrong” vs “could not check” never conflated (unverified / truncated / unavailable are not discrepancies)
  • R5 Void-convention and blind-spot differences recorded, never emailed
  • R6 Alert once per streak; re-arm on clean; changed fingerprint re-alerts once
  • R7 A wedged verifier escalates via operational event — never silent
  • R8 Email gated off at deploy; enabling is config, not code

Out of scope

  • Auto-repair / auto-refold; verify.ts blind-spot or void-sign fixes (deferred follow-up)
  • Statistical anomaly detection; new channels (in-app / WhatsApp); deep-history backfill

Implementation Units

U1. Verification-run table and outcome model

R2 R6deps: none

New schemas/reports/verificationRuns.ts: one upserted row per subject (store × day / store × week) carrying outcome, explained/unexplained summary, fingerprint, streak, last-alerted fingerprint, verified revision.

U2. Result classification layer (pure)

R4 R5 R6deps: none

reports/verificationClassify.ts — pure, no Convex imports (mirrors foldDay.ts). Maps raw verify results to outcomes (weekly incomplete classifies as partial; all six weekly unavailable reasons have enumerated dispositions), partitions differences into explained (void convention, blind spots) vs unexplained, computes fingerprints, owns streak transition rules. Table-driven tests cover every transition including “partial does not clear a mismatch streak unless the differing field was checked clean.”

U3. Verification sweep orchestrator

R1 R2 R6 R7deps: U1, U2

reports/verificationSweep.ts — action pages allowlisted stores; selects settled days (not open, not dirty-marked, not mid-reseed, revision newer than last verified; a legacy day with no certifiedFoldRevision is verified once and re-selected on first stamp); a slow age-based re-verify lane for recent settled days; weekly check gated on reportWeekCurrent.materializedAt advancing (ungated it would dominate the read budget); bounded budgets with sizing arithmetic in comments; per-subject error containment; once-per-streak wedge escalation via operational event; emits the U5 kind only when the email gate is on. Patterns: owedDailyCloseSweep.ts, reports/sweeper.ts.

U4. Cron registration + scheduled-run ledger enrollment

R1 R2deps: U3

STAGE-branched cron in crons.ts (hourly-class, offset from the reports sweep); new cronFamily + interval-map entry kept in agreement; system + per-store ledger rows via best-effort recording. Source-text assertions in crons.test.ts.

U5. Notification kind, payload query, email template

R3 R4 R8deps: U1, U2; emitted by U3

Registry entry (structural dedupe over kind + store + subject + fingerprint + re-arm epoch), fresh-read payload query operations/reportVerificationAlertEmail.ts reading the run row (not live re-verification), template emails/ReportVerificationAlert.tsx rendering unexplained differences as “checked and wrong” and unverified fields separately as “not checked.” Null-suppress if the subject resolved before send; throw on transient failure. Gated off at deploy.

Risks

RiskMitigation
Verify read weight breaches execution ceilingsPer-subject containment; conservative recorded budgets; error + wedge escalation, never silent re-breach
False positives burn alert credibilityRecord-only rollout; voids / blind spots / truncation never email
Sweeps surface truncation in unsized read ceilingsExpected: truncated is a distinct non-alert outcome; sizing deferred follow-up
Alert flap under repeated refoldsRevision-driven selection; fingerprint + explicit re-arm
Cron window math drifts from intervalSingle-source constant; ledger test asserts agreement

  • Delivery gate: docs/solutions/ note + docs/reports/*.html landed-change report; commit → fingerprint → amend ordering
  • Production dry run is a delivery step — both prior verifier defects were invisible to a green suite
