The architectural split

Convex Agent owns through one adapter

  • Runtime thread and message mechanics
  • Model turns, internal streaming, and tool-loop progression
  • Its compatible model/provider invocation
  • Final conversational narrative; its running text streams to the operator as provisional, never-released prose (amended 2026-08-22)

Athena owns

  • The runtime contract, opaque references, and normalized events
  • Operator identity, delegated grants, tenant/store scope
  • Capability semantics, budgets, evidence, and citations
  • Intelligence runs, artifacts, approvals, and operational truth

Request path

1 · IntentAuthorize operator; create or resume an Athena run and opaque runtime thread.
2 · DiscoverReveal compact metadata only for granted packages.
3 · ProgramModel submits import-free TypeScript to one execution tool.
4 · ReadEvery bridge call revalidates authority and invokes a domain read port.
5 · ReleaseCommit a cited answer, reauthorize each view, and record actual receipt separately.

Foundational contracts

A

Capability package

Domain-owned semantic resources with typed filters, projections, bounds, sensitivity, freshness, completeness, evidence, cost, and lifecycle.

B

Agent profile adapter

Selects packages, versions, scope, prompt/context policy, budgets, presentation, and evaluations. It does not alter the kernel.

C

Generated registry

Build-time validated declarations and runtime schemas under an immutable digest with progressive, grant-filtered discovery.

D

Delegated grant

Fail-closed intersection of profile, operator permission, tenant/store scope, lifecycle, emergency clamps, and run policy.

E

Program executor

Replaceable sandbox, Athena-owned validation, async mediated bridge, run-wide limits, one explicit output, and no host facilities.

F

Evidence protocol

Run → attempt → capability call lineage, normalized arguments, usage, result hashes, opaque citations, and derived completeness.

G

Agent runtime adapter

Opaque runtime references, normalized lifecycle events, and bidirectional Athena-owned tool dispatch. Convex Agent is the sole v1 implementation; a contract fake proves separation.

Daily Operations is the first adapter—not the kernel

Selected semantic packages

  • Store-day lifecycle and readiness
  • Sales, pulse, week metrics, payments, top items
  • Operational work, approvals, and queue
  • Registers and cash
  • Activity and timeline
  • Automation evidence
  • Inventory and stock

Extension proof

A synthetic second profile must use the same manifest registration, compiler, grant, discovery, executor, evidence, completion, and UI host contracts.

Pass condition: no Daily Operations imports or branches exist in the kernel, and a second surface requires only conforming manifests plus profile selection.

Hard boundaries

Read-only means structurally unreachable: no mutations, scheduling, network, credentials, filesystem, imports, dynamic evaluation, timers, randomness, ambient clock, raw database access, Convex context, public API re-entry, or function registry. Convex Agent/component imports are also confined to one adapter directory. Future writes use a separate proposal → fresh precondition → Athena approval → admitted domain-command rail.

Runtime decision gate

Single runtime, separate sandbox choice

Convex Agent is the only v1 orchestration runtime and must pass Athena’s adapter contract. @ai-sdk/code-mode remains the leading program-sandbox candidate in a Node 22 Convex action, wrapped behind the generated athena.* facade.

Exit criteria

Deployability, Agent-to-runner bridge, multi-package calls, cancellation, concurrency, hard resource limits, invalid-program rejection, escape testing, and zero host access. If it fails, choose direct QuickJS or external microVM; never node:vm.
