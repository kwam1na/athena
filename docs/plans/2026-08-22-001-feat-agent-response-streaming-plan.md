# feat: Stream the agent's provisional narrative to the reusable host

## Summary

Stream the model's narrative live to the reusable agent host, for any profile, as explicitly provisional text; the committed artifact minted by `completeRun` stays the only released answer. The streamed text is the assistant thinking out loud (a different string from the narrative it later hands to `completeRun`), shown in a visibly provisional container, replaced by the committed answer at commit, deleted on every terminal cause, and accounted for with two markers on the turn binding. The change adds one runtime event to the adapter contract, one minimal delete-only table with a small leaf helper module, two admitted entry points in `turns.ts`, and small hooks in the existing lifecycle clamp, release-suppression path, host finalization, scope removal, and repair sweep — and leaves the executor, budgets, grants, citations, read ports, registry conformance, and the `completeRun` transaction untouched.

---

## Problem Frame

The agent-harness foundation (`docs/plans/2026-08-21-001-feat-athena-agent-harness-foundation-plan.md`, Key Technical Decision 12) buffers the model narrative server-side and streams only server-authored milestones, so that release is one reauthorized transaction and revocation before it is fully recallable. The cost is that a real provider turn shows nothing for several seconds and then the whole answer. Operators expect to watch an answer form. Doing that without weakening release means treating streamed text as a provisional exposure class with its own truthful markers — not as an early release. This plan amends the foundation's R16/R18 exposure semantics and records the amended invariant.

**Prerequisite:** the foundation batch (V26-1259, V26-975, V26-1261, V26-1262, V26-1263, V26-1264, V26-1265, V26-1267, V26-1268, V26-1272, V26-1273; integration branch `codex/agent-harness-foundation-delivery`) is merged to `main`. Paths are repo-relative under `packages/athena-webapp/` unless stated and name modules that branch lands.

## Requirements

- R1. The narrative streams to the operator as it is generated, for any profile whose policy enables it, through the reusable host; no surface-specific branch in the streaming path.
- R2. Streamed text is provisional: shown in a persistent, visually distinct container whose copy says the text is not verified and must not be acted on; never citation-bearing, never a citation source, never in projected history or a prompt, never promoted to the standard retention class.
- R3. The committed artifact is the only released answer; because `completeRun` is a mid-turn tool call whose `narrative` is an independent string, the provisional text is replaced, not morphed, and the operator is told it may differ.
- R4. Provisional text is deleted on every terminal cause: inside the lifecycle's terminal clamp for non-`completed` terminal statuses (cancel, failure, kill switch, fence repair) in that transaction — placed outside the clamp's binding-state guard, keyed on `run.turnBindingId` alone, the same placement rule as the `suppressReleaseWithCtx` call; in `suppressReleaseWithCtx` for post-commit revocation; inside the host's `finalizeTurnWithCtx` transaction at the end of every driven turn (covering successful commit and commit-then-provider-failure) outside the commit transaction; and by scope removal's own scope-indexed delete. A row past its short expiry is reported as `stalled` by the preview (a servable arm with no text, not a refusal), dropped client-side when the returned expiry passes, and deleted by the repair sweep. The preview query never writes.
- R5. The turn binding records `provisionalReleasedAt` (first text readable) and `provisionalViewedAt` (best-effort client acknowledgement, weaker than `operatorViewedAt`; refused unless `provisionalReleasedAt` is already set, so it can never outrank the server fact). The turn-scoped projection derives `provisionalExposurePresumed = provisionalReleasedAt !== undefined` (the investigative fact) and `revokedAfterProvisionalExposure = provisionalExposurePresumed && (terminalRevoked(run) || binding.releaseSuppressedAt !== undefined)`, where `terminalRevoked` is the predicate `resolveAttemptExposure` already uses for `revokedAfterProviderExposure`. Markers are irrevocable and reachable through a turn-keyed entry point for zero-attempt turns.
- R6. One new normalized runtime event (`narrative_delta`) with a protocol-version bump, emitted by both the contract fake and the Convex Agent adapter and proven by the shared contract suite; no runtime-native type leaves the adapter directory.
- R7. No Convex Agent component stream persistence; the component allowlist (`input | turn | projection`) is unchanged.
- R8. Provisional text reaches the browser only through an Athena-owned reactive query separate from the turn view that reauthorizes on every read and returns `not_found` until ownership is established; the flush is a host-only internal mutation (it authorizes the grant's pinned operator, not its caller); streaming writes the binding only once (`provisionalReleasedAt`), never per delta, and never touches the run record.
- R9. Rendering uses the foundation's inert `AthenaAgentSafeText` in a provisional mode (paragraphs, lists, inline spans only; rules dropped, headings downgraded, quotes and fenced code flattened), re-parsed from the whole buffer every render so every prefix is inert; no browser-side persistence; the panel's single scroll container follows the growing text only while the operator is at the bottom; the live region announces at most one coalesced change per draft and focus moves only on a terminal `hostState` transition, onto the answer heading on commit, or once onto a mid-run `withdrawn` notice — never on streaming, reset, pause, or stall, and never twice for the same terminal outcome.
- R10. Enablement is a required, validated, kernel-visible per-profile policy (`provisional_streaming` | `buffered`) in the compatibility digest, enforced server-side by the flush (read from the digest-pinned registry profile after `reauthorizeGrantWithCtx`) and reported by the preview from the live registry profile (both drift directions are fail-safe: a live `buffered` reads as `disabled`, and a fenced run can never produce a servable row; a `buffered` profile never gets a row) and proven end to end by a second, `buffered` test profile alongside the existing shared test profile (which stays `provisional_streaming` because every host and turn test pins it).
- R11. Deploys behind the existing one-command compatibility fence.
- R12. The foundation's "no partial narrative reaches the browser" tests are rewritten to the amended invariant ("the narrative never enters Athena's durable record, projected history, a citation, or a prompt, and never survives a terminal cause"), not deleted.

## Scope Boundaries

- No streaming of tool-call arguments, program source, capability results, reasoning, or any non-text part.
- No per-chunk citation validation or streamed citations.
- No change to `operatorViewedAt`, the `completeRun` transaction, executor, budgets, grants (including the closed `DelegatedAuthorityPurpose` set — the flush reuses the existing release purpose; accepted), read ports, or capability conformance.
- No component stream tables, `saveStreamDeltas`, `syncStreams`, or `@convex-dev/agent/react` in the browser; no second runtime; no TanStack-path streaming.

### Deferred to Follow-Up Work

- Reveal smoothing tuned from measured latency; provider finish reasons as a stop reason; a general cancel-poll shortening; a boundary rule banning react-markdown from the agent host.
- Faster closure of a run left at `running` by a crashed host. The foundation's stale-binding sweep now fails such runs (`turn_host_stalled`) at the 15-minute abandon window; this plan bounds the *readability* of the draft much tighter — the row's 5-minute expiry, the client-side drop, and the repair sweep — and does not shorten the run's own window.

## Key Technical Decisions

- **In-process streaming; no component persistence.** The adapter calls `agent.streamText` with `saveStreamDeltas: false`, forwards only `text-delta` parts to the narrative (default-deny for content), coalesces them (~200 ms or sentence boundary), and emits `narrative_delta { draftOrdinal, text }` (no stream identifier and no per-delta index — the envelope's `sequence` and `turnRef` already order and identify every event, `draftOrdinal` identifies the draft, and the kernel mints every opaque ref) through `hooks.onEvent`. Control parts are still observed for lifecycle: `error` terminalizes the turn as `failed` (provider failure — it arrives as a stream part, not a throw), `abort` as `canceled`, step markers advance `draftOrdinal`. Rejected: Agent-native delta storage and a hybrid envelope.
- **`narrative_delta` is a versioned contract evolution.** Protocol version bumped because the descriptor's protocol version is a pinned literal type and the validator is fail-closed; the digest moves and the deploy uses the fence.
- **One minimal delete-only table and one leaf helper module.** `agentProvisionalNarrative`: `runId`, `turnBindingId`, `storeId`, `organizationId`, `text`, `draftOrdinal`, `truncated`, `egressClass`, `retentionClass` (the literal `"short_lived"`, so the table speaks the sibling content tables' vocabulary and `dataGovernance` sees no parallel framework — expiry still belongs to the repair sweep, not the retention sweep), `updatedAt`, `expiresAt`; indexes by binding, by `expiresAt`, by store, by organization; no state column; nothing retained after deletion; text capped at `AGENT_TOOL_NARRATIVE_MAX_BYTES` (overflow sets `truncated` and keeps streaming). `convex/agentHarness/provisionalNarrative.ts` is a leaf (imports only schema/values and carries its own TTL literal, never importing from `turnBindings.ts`) exporting the row helpers — upsert, delete-by-binding, expiry delete — so `lifecycle.ts` (itself a leaf), `completionOutbox.ts`, `retention.ts`, and `turns.ts` can all call them without a cycle (`turns.ts` imports those modules, so the helper cannot live there); `importBoundary.test.ts` asserts that allowlist. Rationale: the prompt-payload table was rejected because its expiry sweep patches the run's grant for every expired row; the helper module exists only because the repo has no cycle detector and the delete has five call sites. The helper exports its own `AGENT_PROVISIONAL_NARRATIVE_TTL_MS` literal (5 minutes — the same value as the step-staleness window but not imported from `turnBindings.ts`, which would close a cycle through `lifecycle.ts`); the flush in `turns.ts` refreshes `expiresAt` from it and U3 asserts the preview's `stalled` and the sweep's deletion at that bound.
- **Single-flight, full-overwrite flushes; the flush is the enforcement point and a host-only internal mutation.** The host keeps one flush in flight and coalesces newer text behind it (serialized by construction), so the row is overwritten and a new draft overwrites the previous one. The flush is a named ref in `AgentTurnHostRefs` (mirrored in `PRODUCTION_REFS` and `TEST_TURN_REFS`), defined in `turns.ts`; it reads `narrativePolicy` from `admission.registry.profiles[grant.profileKey]` (the digest pin in `reauthorizeGrantWithCtx` guarantees it is the pinned profile) and refuses and deletes for `buffered`; calls `reauthorizeGrantWithCtx` (refuses non-`running` runs; covers enablement and the epoch fence) and also refuses when the turn's stamped egress class — `requestSummary.egressClass` on the provider-invocation row, so the rule holds on the very first flush before any provisional row exists — outranks the verdict's `runtimeGrant.egressClass` (reading the stamped value through the existing `normalizeEgressClass` — `requestSummary` is an open record and `egressClassRank` returns -1 for an unknown string, so an unrecognized class must normalize to `restricted`, not rank below `operational` — then comparing with the kernel's `egressClassRank`, as `turns.ts`/`completionOutbox.ts` do for their own comparisons; `authorityShrunk` is a different, narrower signal — a capability or projection narrowing that the kernel records as evidence, not a denial), so a mid-turn egress downgrade deletes the row instead of leaving it at rest unreadable; refreshes `expiresAt` to the mutation's own clock + `AGENT_PROVISIONAL_NARRATIVE_TTL_MS` (the host-passed `now` is used only for `updatedAt`, so the exposure bound stays a server fact while the `committing` comparison stays on the host's single clock); stamps the egress class on insert from the provider-invocation row (refusing without it; the row is inserted once per turn and a provisional row never survives into a re-prepare, so no re-stamping exists); sets `provisionalReleasedAt` once; inserts only while the run is `running` and `operatorReleaseCommittedAt` is unset (binding step `running` or `completion_prepared`, so a retryable `completeRun` failure can resume); and on any refusal deletes the row in the same transaction. OCC may fail a flush against concurrent turn writers; it is dropped and the next carries the full text.
- **Deletion per terminal cause, never inside the commit transaction.** (1) `clampRunChildrenWithCtx` calls the delete helper for every terminal status except `completed` — cancel, failure, kill switch (via `cancelAgentRunWithCtx`), fence repair — atomically with the transition; `completed` is excluded because the commit transaction itself ends in the clamp. (2) `suppressReleaseWithCtx` calls the delete helper outside its `if (!already)` guard (post-commit revocation never transitions the run; a second suppression from the outbox cron must still clean up). (3) `finalizeTurnWithCtx` calls the delete helper inside its existing transaction, above the `already_terminal` early return, at the end of every driven turn — covering successful commit and commit-then-provider-failure (where the later `failed` transition does not re-clamp). (4) Scope removal's existing scope-indexed delete covers the new table (and still cancels active runs, which clamps). (5) Dead host: the preview refuses an expired row and returns `expiresAt` so an open pane drops the text client-side when it passes, and the repair sweep gains a pure-delete phase over the expiry index (5 minutes in production, 60 elsewhere — so a dead-host row is unreadable after the 5-minute TTL but stays at rest until the next sweep: about 10 minutes in production, about 65 on non-prod deployments, an accepted bound) whose result carries a deletion count — and, because `repairSweep` is a cron-invoked `internalMutation` whose return value is discarded, one `console.log` line from the sweep whenever the expiry phase deletes anything (the count plus the sweep's other counters), read via `bunx convex logs` exactly like the `driveTurn` line. Rejected: a buffer write inside `completeAgentRunWithCtx`; relying on the 6-hourly retention sweep; a retained digest; a stored state column.
- **Quiescence at `completeRun` with drain and a resume rule; no extra server fact.** On `tool_call_requested` with the `completeRun` tool id (emitted before the tool runs, and awaited), the host sets its stop flag, then awaits its in-flight flush through the same settle-never-rethrow wrapper `runtimeHost.ts`'s milestone queue already uses (an OCC-failed or refused flush is dropped, and the drain inside `hooks.onEvent` must not reject the awaited `emit`), so the commit transaction is never contended; the panel shows `committing` from the existing `finalizing` milestone already carried by the turn view (it fires after the cheap denials and before the commit), gated by one clock — the host passes the same `now` it stamps on the `finalizing` milestone into the flush, which stores it as the row's `updatedAt` (the preview returns it), so `committing` holds while the newest `finalizing.at` is at or after `updatedAt`; a resumed draft's first flush moves `updatedAt` past it, which is what makes `streaming` return after a refused commit even though the milestone array only ever grows within a turn (capped at `AGENT_TURN_PROGRESS_CAP`, unreachable under `maxAttempts: 3`) and milestones can arrive late or be observed by a remounted panel. If the tool completes with any non-success outcome (`denied`, retryable `failure`, or `protocol_violation`), flushing resumes with a new `draftOrdinal`; on success the binding's commit fields drive `superseded` and `finalizeTurn` deletes the row. Rejected: a `quiescedAt` row write (nothing it guarded against exists, since `emit` awaits the hook and the tool boundary already advances the draft).
- **The streamed prose is a different artifact from the committed answer** (`completeRun`'s `narrative` is a tool argument). The container says the assistant is thinking out loud, the text is not verified and must not be acted on, and the answer will replace it; the swap is a replacement. Accepted, named risk: an operator can read claims that never pass the citation gate.
- **Provisional presentation is a separate client-derived field, not new members of the kernel's `AgentHostState`.** `useAthenaAgentRun.ts` exposes a `provisionalState` alongside the existing `hostState` (the closed, server-declared `AgentHostState` union in `shared/agentHarness/profile.ts` is untouched). Precedence, first match wins: preview `disabled` (a `buffered` profile that never released) → milestone-only view, no notice; a release observed on either query (`provisionalReleasedAt` on the turn view or `released` on the preview — so a turn that never showed text, such as an `awaiting_first_text` cancel or a never-released `buffered` turn, never withdraws) and no commit observed (the view's `phase` is not `completed`, so a post-commit suppression stays on the answer surface's own `terminal_denied` and never flips `superseded` back to `withdrawn`), and either the preview itself returned `withdrawn` (epoch advance, disablement, kill switch, and a post-release policy flip all cancel the run moments later through `repairFencedRuns`/`cancelActiveRunsForProfile`, and an egress downgrade fails the turn at its next capability call — the preview simply sees the withdrawal first, so the notice must never promise an answer; the server ladder is authoritative here, as it is for `disabled`; when disablement or membership loss also makes `getTurnView` `unavailable`, the panel's existing `terminal_denied` and this notice share the single focus move) or run terminal other than `completed` (abandonment is not a separate trigger: the view does not project it and every abandonment co-occurs with a terminal run) → `withdrawn` (the notice itself is rendered with `role="alert"`, reusing the panel's existing `denial` block pattern, so its closed-vocabulary reason is announced regardless of focus; focus moves once to the notice's own ref — the `answerHeadingRef`/`sourceHeadingRef` pattern — because the panel's existing focus effect only targets `statusRef` on a `hostState` transition and the run is often still `running` when the preview withdraws; the notice focus is not a second effect but a new branch inside the panel's one existing focus effect, which is re-keyed on both `hostState` and `provisionalState` and keeps its single `previousState` ref, now holding `{ hostState, provisionalState }` (the equality early-return moves inside both `hostState` branches — the `statusRef` one and the `answerHeadingRef` one — so a `provisionalState`-only change re-fires neither, and a null previous value on mount never counts as a `withdrawn` edge): it evaluates the terminal `hostState` transition first and returns; otherwise the `hostState` branches simply do not fire, and the `withdrawn` edge then moves focus only while `hostState` is `running` (the one operative predicate — the point being that every other state has either already performed its own move or is a transient reconnect/idle window the mount guard covers), and never while the composer textarea is the active element (the panel keeps it editable mid-stream, so an operator typing a follow-up must not lose keystrokes; the `role="alert"` still announces), so Stop-then-withdraw keeps the operator's `cancellation_requested` focus and the notice only announces; because every withdrawal cause also ends the run moments later (which the hook maps to `terminal_denied`, a `statusRef` target), a "focus already claimed" latch that stores the `turnId` it was set for (the panel's existing per-turn refs — `notifiedTurnRef`, `acknowledgedTurnRef` — use the same turnId-keyed shape, and the panel stays mounted across New thread — it is only unmounted on close, where the latch and `previousState` reset together, which is consistent with the remount rule — so a bare boolean would stick for the session) and is cleared whenever `hostState` enters `submitting` or `idle` — `activeTurnId` lags the next turn's start transition, so keying alone would swallow its "Starting your request…" focus move — and also whenever the effect actually performs a move to `statusRef` or `answerHeadingRef` (so after a withdraw-then-commit the later `terminal_denied` from a refused acknowledgement still moves focus off the unmounting answer article) — suppresses only that later `terminal_denied` `statusRef` move — never the `answerHeadingRef` move (the answer article has no live region, so focus is its only signal; an egress-downgraded turn that still commits normally shows the notice and then the answer, two moves) and never the operator's own `cancellation_requested` move — so "the existing target wins" when both land together, the notice wins when it lands first, and a withdrawn draft never yields two focus moves for the same terminal outcome); the preview's `superseded` or the turn view's `phase === "completed"` (the view carries no commit field; `completed` implies committed because `finalizeTurnWithCtx` fails an uncommitted turn) → `superseded`; newest `finalizing.at` at or after the row's `updatedAt` → `committing`; row present with a `draftOrdinal` newer than the ordinal the client last rendered → `reset` (edge-triggered: the previous text clears immediately with a brief visual cue, one polite live-region announcement from the closed vocabulary so screen-reader operators get the same signal, and no focus move; the hook initializes its last-rendered ordinal from the first row it paints — so a mount or reconnect never reads as a reset, mirroring the `committing` mount guard — and records the new ordinal on that paint, so the state lasts one render before the level-based states below apply); row present with `truncated` → `paused_at_limit` (the text stays; one polite closed-vocabulary line through the same live region says the draft reached its display limit — copy deferred like every other state); row present and unexpired → `streaming`; run running with `provisionalReleasedAt` unset and no row → `awaiting_first_text` (today's milestone-only view — the opening tool phase produces no narrative); run running with a release observed and the preview reporting `stalled` (released, no live row: refused-and-deleted, or past expiry — the server rung; the client also drops a `streaming` row past its returned `ttlMs`) → `stalled` (non-terminal; no focus move; the text clears and a polite closed-vocabulary line replaces it — "the draft paused" followed by a pointer to the controls the panel already keeps enabled ("you can stop this request or start a new thread"), because the causes that reach this state (a dead host, an expired row) are exactly the ones a crashed-host gap can leave unresolved indefinitely, so this line must not be the operator's last signal — through the same live region as `reset`, so neither screen-reader nor sighted operators see text silently vanish under a "running" milestone); no match (including a never-released turn whose view went `unavailable`, whose `terminal_denied` the panel already renders) → `none`, rendering nothing. The preview returns `updatedAt` and a server-computed `ttlMs` alongside `expiresAt` so neither `committing` nor the client-side drop depends on browser clock skew or milestone arrival order. Scroll: the panel's single scroll container follows the growing text while the operator is at the bottom, stops following once they scroll up, and re-anchors on terminal states.
- **Two markers on the turn binding, one turn-keyed projection.** `provisionalReleasedAt` (once, by the first flush; also projected onto the `getTurnView` result and returned as `released` by the preview, because the preview subscription ends at terminalization while the view goes `unavailable` on disablement or membership loss — the host reads whichever query is still answering) and `provisionalViewedAt` paired with `provisionalViewedByActorRef` like the existing `operatorViewedAt`/`operatorViewedByActorRef` (read by `resolveTurnExposure`, which reports exposure as confirmed when it is set and presumed when only the release marker is; first-write-wins, via `acknowledgeProvisionalView`, which runs the same full reauthorization as `acknowledgeTurnAnswer` and refuses unless `provisionalReleasedAt` is set — mirroring how `acknowledgeOperatorViewWithCtx` refuses without a committed release). `resolveTurnExposure({ run, binding })` in `evidence.ts` derives `provisionalExposurePresumed` and `revokedAfterProvisionalExposure` (using the existing `terminalRevoked` predicate — `canceled || failed`, the same coarse basis `revokedAfterProviderExposure` uses, so a provider timeout after exposure also sets it — or `releaseSuppressedAt`); `resolveAttemptExposure` delegates for the shared fields; a turn-keyed `describeTurnExposure` internal query in `turns.ts` (mirroring `describeAttemptExposure`) makes it reachable for zero-attempt turns. A refused acknowledgement on a revoked turn also deletes the row, mirroring `acknowledgeTurnAnswer`'s refusal branch including its `ownTurn` guard — refusals before ownership is established (`not_found`, `not_your_turn`, `operator_unauthorized`) write nothing. Rejected: per-draft counts and timestamps (nothing derives from them); a reason enum (the run records no structured revocation reason — only the free-form `error.diagnostic` / `binding.abandonReason` text, which never reaches operator copy: the withdrawn notice is selected from `AthenaAgentPresentationAdapter.ts`'s closed vocabulary keyed on the structured facts already projected — the preview's closed `reason` on `withdrawn` — through one small provisional-withdrawal branch in the adapter whose copy states only what happened to the draft ("the draft was withdrawn" plus the closed reason's headline) and never what will happen to the answer, because every mid-turn cause that withdraws a draft also ends the run (fence and disablement cancel it through their sweeps, an egress downgrade fails it at the next capability call); the answer surface's existing `terminal_denied`/answer states carry the rest — the turn view's closed `error.code` and its `describeTurnErrorForOperator` headline, `answer.suppressed`, abandonment; `error.diagnostic` and `abandonReason` are never projected to the browser).
- **Egress class comes from the existing provider-invocation row.** The flush stamps `requestSummary.egressClass` when it inserts the row; the invocation row is inserted once per turn and its `requestSummary` is write-once provider evidence (finalization patches only the response side), and a provisional row never survives into a re-prepare. Pre-read narrative is over-classified (conservative) — and because the stamped class is the *turn* class, which folds in projected history, it can outrank the operator's current capability-derived grant: in that case the first flush refuses and deletes and the preview withdraws on an otherwise healthy turn, which is the intended fail-closed behaviour and gets its own U3 edge-case scenario; the committed answer's class may be lower — intended.
- **Two admitted entry points in `turns.ts`.** `getTurnNarrativePreview` (read definition like `turnRead`; `not_found` until ownership is established; returns a discriminated union in the shape every other `turns.ts` result uses: refusal arms are bare — `{ state: "not_found" }`, `{ state: "withdrawn", reason, released }` — and of the servable arms only `streaming` — the one arm that always has a live, unexpired row — carries `{ released, text, truncated, draftOrdinal, updatedAt, expiresAt, ttlMs }`; `disabled`, `awaiting_first_text`, `stalled`, and `superseded` are `{ state, released }` with no text and no row fields (a `superseded` in the window before finalize serves nothing — the committed answer is the only release); because `reauthorizeTurnAccess`'s refusal arm carries only `reason`, the preview re-reads the binding it already loaded to fill `released` on the `withdrawn` arm — so a refused reader (e.g. after an egress downgrade while the flush keeps writing) cannot watch `updatedAt` tick or `draftOrdinal` advance; `reason` is the closed refusal reason on `withdrawn`, mirroring `getTurnAnswer`'s `unavailable(reason)`, and `released` is the binding's `provisionalReleasedAt` presence, carried on every post-ownership state so the host's guard has a source even when `getTurnView` has gone `unavailable`; returns the non-terminal `disabled` state for a `buffered` profile that never released (milestone-only view, no notice), and `withdrawn` with reason `policy_disabled` when the profile flipped to `buffered` after a release — the operator's vanished text gets a notice) and `acknowledgeProvisionalView` (operation definition like `turnManageOperation`).
- **Required profile policy, enforced by the flush and reported by the preview.** `narrativePolicy: "provisional_streaming" | "buffered"` (no default), validated like every other enum field, `provisional_streaming` on both shipped profiles and on the existing shared test-port profile (every host and turn test pins it), plus a second `buffered` test profile composed into the test ports — added to `TEST_REGISTRY`, included in `TEST_ENABLEMENT`'s baseline (profiles are default-off), given its own presentation adapter, and selectable through a profile-id override on `seedRecordedTurn` — so the buffered scenarios exercise a started turn; rollback to `buffered` is server-enforced (the adapter-wide narration directive stays in place — the narration then simply lands in `turn_completed.narrative` as today, which is harmless) and renders as `disabled` for turns that never released — a turn whose text was already on screen withdraws with the `policy_disabled` reason instead of vanishing silently.
- **Provisional rendering is a mode of the existing renderer.** `AthenaAgentSafeText` gains a provisional mode (paragraphs, lists, inline spans only), re-parses the whole buffer per frame, renders inside a persistent provisional container, never persists text client-side, announces at most one coalesced change per draft, and moves focus per R9 (terminal `hostState` transitions, the answer heading on commit, or once onto a mid-run `withdrawn` notice); all state copy — including the renderer's "shortened for display" notice when it fires inside the provisional container — comes from `AthenaAgentPresentationAdapter.ts`.

## Open Questions

### Resolved During Planning

- Persistence: a minimal delete-only table plus a leaf helper module (prompt-payload reuse rejected for the sweep side effect; helper placed to avoid import cycles).
- Ordering: single-flight flushes instead of a compare-and-set key; drain at the `completeRun` request.
- Dead hosts: expiry refused server-side, dropped client-side on the returned clock, deleted by the repair sweep.
- Deletion timing: clamp (non-`completed`), `suppressReleaseWithCtx`, `finalizeTurnWithCtx`, scope removal; never the commit transaction.
- `committing`: derived from the existing `finalizing` milestone compared against the row's `updatedAt`, both stamped from the host's one `now`; no new server write.
- First-token latency: `awaiting_first_text` (milestone-only view) until `provisionalReleasedAt` exists; `stalled` only after it; a `buffered` profile is the standing `disabled` state.
- Host typing: provisional presentation is a separate `provisionalState` field; the kernel's `AgentHostState` union is untouched.
- Re-prepare egress patching: dropped — unreachable, and the invocation row is provider evidence.
- Reset across tool steps and resumed attempts: yes, one draft ordinal each, client-detected.
- Deploy posture: fence → deploy → direct-harness smoke + adapter smoke → enable → one operator turn (non-prod driver; prod: first monitored turns).

### Deferred to Implementation

- Coalescing cadence (start ~200 ms / punctuation; tune from measured latency). The flush-before-`tool_call_requested` rule in U2 is fixed, not tunable.
- Streaming mock chunk shape in the contract harness and smoke action.
- Exact copy per host state in `AthenaAgentPresentationAdapter.ts` following `docs/product-copy-tone.md`.

- Deletion: clamp (non-`completed`); `suppressReleaseWithCtx` (outside the guard); `finalizeTurnWithCtx` (above `already_terminal`); scope removal; repair-sweep expiry phase (logs its count when nonzero).
- Preview ladder: the first rungs delegate to the existing `reauthorizeTurnAccess` in the same file (delegated operator → binding/store → grant owner, `not_found` until here → live authority incl. enablement) rather than a second hand-rolled ladder → epoch fence via the already-imported `checkRunEpochFenceWithCtx` (a digest-moving deploy withdraws immediately instead of waiting for the next flush or the fenced-run repair) → profile policy (`disabled`, non-terminal) → egress rank (compared, after the same `normalizeEgressClass` read the flush uses, against `requestSummary.egressClass` on the write-once provider-invocation row — `by_runId`, inserted once in `prepareTurnWithCtx`; before that row exists the turn is still queued, nothing has been released, and the rung is skipped so the ladder falls through to `awaiting_first_text` rather than a false `withdrawn` — never against the provisional row, so the verdict survives the row's deletion and a remount after an egress downgrade still shows `withdrawn`, not `stalled`) → not abandoned/suppressed → run state (`running` continues; `completed` → `superseded`, because `completeRun` flips the run mid-turn and the row survives until `finalizeTurnWithCtx`, so a successful commit must never read as a withdrawal; `canceled`/`failed` → `withdrawn`) → expiry; return the discriminated union (bare `not_found`; `withdrawn` with only `reason` and `released`; metadata and text only on servable arms) with a closed `reason` on `withdrawn` and `released` on every post-ownership state (`buffered` after a release → `withdrawn`/`policy_disabled`, never `disabled`); never write.
- Acknowledge: full turn reauthorization, owner only, `provisionalReleasedAt` required, first-write-wins `provisionalViewedAt`.
- Exposure: two markers + derived fields via `resolveTurnExposure`, reachable through `describeTurnExposure`.

- Error path: operator cancel mid-stream → the clamp deletes the row in the same transaction; prior `provisionalViewedAt` preserved.

## System-Wide Impact

- **Interaction graph:** adapter `emit` → host `hooks.onEvent` → single-flight flush (host ref in `turns.ts`, leaf helper) → row → preview → host; `completeRun` request → drain and stop / non-success → resume / success → `finalizeTurnWithCtx` deletes; clamp → delete on non-`completed` terminal transitions; `suppressReleaseWithCtx` → delete; scope removal → delete; expiry → preview refuses, client drops, repair sweep deletes and counts.
- **Error propagation:** a mid-stream provider `error` part terminalizes the turn as `failed` (a thrown network error takes the existing catch path) and the clamp or `finalizeTurnWithCtx` deletes the row; a refused or OCC-failed flush is dropped and the next carries full text; preview failures refuse (`not_found` before ownership, `withdrawn` after; `disabled` is a state, not a refusal).
- **State lifecycle risks:** late deltas after commit (drain + insert guard); commit-then-failure (`finalizeTurnWithCtx`); post-commit revocation (`suppressReleaseWithCtx`); dead host (expiry + client drop + repair sweep); re-creation after deletion (insert guard).
- **Parity:** fake and adapter emit identical sequences; both shipped profiles declare the policy; the host renders both plus the buffered test profile.
- **Unchanged invariants:** `completeRun` remains the only release and its transaction is untouched; citations resolve only against committed evidence; `operatorViewedAt`, the persistence allowlist, budgets, grants, read ports, executor, and capability conformance are untouched.

## Risks & Dependencies

| Risk | Mitigation |
|------|------------|
| Provisional text read by an operator whose authority later shrinks | Per-read reauthorization; flush reauthorizes and deletes on refusal; clamp and suppression delete; expiry with client drop; stamped egress class |
| Unverified text at rest after a successful commit or post-commit failure | `finalizeTurnWithCtx` deletion; expiry and repair sweep; U3 asserts the row is gone |
| Operator acts on claims that never pass the citation gate | Accepted, named: provisional container with not-verified copy; markers record it |
| Model-fabricated UI chrome | Provisional renderer mode; "system notice" fixture |
| `provisionalViewedAt` under-reports receipt | `provisionalExposurePresumed` is the investigative fact; revocation flag uses the existing predicate and suppression |
| Token-rate writes amplify reads or contend with the commit | Dedicated row and query; single-flight; drain at `completeRun`; one binding write per turn; clamp skips `completed` |
| Frozen pane after a refused commit | Resume on any non-success outcome; insert guard allows `completion_prepared` |
| A non-host caller writes text into an operator's pane | The flush is host-only internal, not admitted as public ingress |
| Reasoning or tool parts reach the browser | Default-deny part allowlist |
| Protocol/digest bump strands in-flight runs | Fence deploy; repair sweep |
| Chunk-split markup defeats sanitization | Whole-buffer re-parse; every-prefix fixtures |
| Already-painted text cannot be recalled | Accepted: server deletion plus connected-view removal; no client persistence |
| Screen-reader spam, flashing UI, or scroll fighting | coalesced announcements (one per draft), reduced motion, sticky-follow only at the bottom |
