Athena · Reviewed implementation plan · 2026-08-03

Scale Units moved into top-mover and granular tabs

Extend Athena's existing asynchronous range lifecycle with resumable movement snapshots, then deliver one bounded 20-row view to the shared Weekly, Overview, and demo sheet.

Completion guarantee: once a valid Units moved range of up to 92 days is admitted, SKU count and backend batch size remain pending work—not a terminal unavailable result. Admission overload is retryable backpressure that performs no write or scheduling.

Rollout prerequisite: snapshot trust depends on certified fold revisions that no existing row carries. The fold path stamps them going forward, and existing history acquires them through a fold-version bump plus the per-store foldVersionRepair run — a required one-time migration before the UI is enabled. Stores outside the reporting sweep allowlist receive an explicit "not available" state rather than an indefinite pending state.

Revised backend lifecycle

Authorize and admit→ Queue→ Accumulate bounded days→ Finalize ranks→ Publish immutable snapshot

The plan now reuses reportRangeResult as its request header instead of introducing a parallel framework. Request kind, range, contract version, and the bounded included-day revision vector define snapshot identity. Request-owned child rows keep documents bounded, and known-dirty or uncertified days wait for their canonical fold instead of publishing stale data.

Security and reliability boundaries

  • Only a full administrator with report-generation authority can create work; demo/read-only principals can only read permitted results.
  • Equivalent requests deduplicate. Saturated admission returns a generic retry interval with no durable write or scheduled continuation.
  • Phase/version fencing prevents duplicate workers from applying one source day or rank interval twice.
  • An atomic batch mutation lets defects escape and roll back; a private action records retry metadata afterward in a separate mutation.
  • Prompt continuations provide responsiveness and a globally indexed cron scan recovers lost work.
  • Every header, child, page lookup, and hydrated SKU is bound to the authorized store.
  • Public errors expose a generic code and correlation id, never raw worker exceptions or source lineage.
  • Expired children are removed in fair, resumable batches before their unreferenced header.

Review decisions

  • Kept exhaustive granular browsing and absolute-net ranking because both were explicitly confirmed.
  • Rejected the overview timestamp as a correctness watermark.
  • Treated revision certification as an explicit migration (fold-version bump plus per-store repair) after review showed clean historical days never refold on their own.
  • Gated generation on the sweep store allowlist so a store that can never certify reports a truthful "not available" instead of waiting forever.
  • Chose polling for waiting states (which deliberately write nothing) and subscription only after admission.
  • Scoped R11's scroll restoration as new cross-navigation machinery; the sheet's in-mount scroll map cannot survive the SKU drill-down unmount.
  • Keyed completed movement snapshots by request kind and bounded clean-day revisions so changed source data cannot reuse a stale result.
  • Reused the existing range lifecycle instead of adding a second request framework.
  • Removed stale-while-refresh generation complexity that no requirement demanded.
  • Kept the legacy movement query during additive rollout so old clients remain compatible.
  • Deferred bespoke monitoring dashboards and broader range-framework generalization.
