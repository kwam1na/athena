Inventory Import Cost Overlay

A narrow extension of Inventory Import that freezes one legacy cost column, applies prospective valuation corrections through Athena’s existing inventory-effect rail, and supports exact audited run-level undo.

Type: feat Status: active Created: July 28, 2026 Multi-lens review: aligned 5 implementation units Financial-data boundary
Scope Design Units Risks Verification Canonical markdown

Outcome and boundaries

Full administrators select one disambiguated column from the currently loaded saved review, preview its cost against anchored Athena SKUs, and confirm a durable run. Rows with a valid source cost and missing Athena cost default selected; missing or invalid source cells are ineligible and known-cost overwrites remain explicit.

Apply

Revalues current on-hand inventory and future cost accounting without changing stock, availability, price, identity, lifecycle, or historical sales.

Provisional rows

Update the anchored SKU immediately and retain explicit overlay provenance so later finalization preserves the selected cost.

Undo

Appends compensating corrections that restore the exact pre-run basis for unchanged rows and reports later-changed rows as stale. It is best-effort compensation, not a global rollback guarantee during normal store activity.

Explicit exclusions

  • No historical sale-cost or profit rewrite.
  • No manager-elevation access or per-row undo.
  • No generic backfill framework or wholesale Inventory Import rewrite.
  • No stock, availability, selling-price, identity, or lifecycle mutation.
  • No unrelated cleanup of active rows that already carry finalization evidence.

Technical shape

Saved review + shared source projection
→
Frozen run + per-SKU rows
→
Fenced valuation apply / compensation

Decisions that keep the change small

  • Extract one shared raw-source projection and retain the current import parser as its Athena-field adapter.
  • Use a domain-specific run plus indexed row documents; do not invent a reusable jobs platform.
  • Reuse the existing SKU valuation correction for apply and add one narrow exact-basis sibling for compensation.
  • Create a focused Cost overlay view and extract only review primitives both workspaces genuinely share.
  • Use the current operation-admission definitions and wrappers; manager-enabled import APIs do not gain cost fields.
  • Bound draft construction and confirmation sealing with durable cursors instead of adding a generic jobs framework.
  • Read saved chunks individually in one dedicated Node-runtime internal action, parse within the existing capped review envelope, and call normal internal mutations to persist deterministic rows in bounded transactions.
  • Use two narrow financial checkpoints: acknowledge the exact source column as unit cost, then review aggregate valuation impact and the largest SKU changes before sealing.
Primary correctness boundary: the current correction helper can set a unit cost but cannot reconstruct a mixed prior costed/uncosted basis. Undo therefore freezes the complete pre-state and restores it through a new append-only exact-target valuation correction.

Implementation units

U1 · No dependencies

Preserve and freeze arbitrary cost-source evidence

Share CSV/JSON source projection, strict money outcomes, and exact saved-version hydration while preserving all established parser behavior.

Proof: parser characterization, duplicate-column identity, invalid-state distinctions, and exact chunked/legacy review hydration.

U2 · Depends on U1

Persist frozen overlay runs and full-admin contracts

Add the minimal run/row ledger, a dedicated capped Node construction action, durable cross-page decisions, duplicate-SKU handling, cursor-bounded construction and confirmation preparation, aggregate impact totals, paginated reads, and admitted full-admin commands and reads.

Proof: authorization denials, capped parse and bounded write recovery, valid-source and missing-Athena selection, explicit overwrite, prepared-summary integrity, abandon/reopen behavior, stable run scope, and semantic replay conflicts.

U3 · No dependencies

Add exact-basis valuation compensation

Extend the existing inventory-effect boundary to restore frozen costed quantity, uncosted quantity, known pool, currency, and SKU cost through new correction evidence.

Proof: mixed-basis restoration, missing-versus-zero cost, stale/deficit rejection, replay, activity, revision, and projection behavior.

U4 · Depends on U2 and U3

Orchestrate fenced apply, provisional propagation, and undo

Use bounded internal workers with durable row states and monotonic epochs, preserve cost through both finalization paths, and prevent queued apply work from crossing into undo.

Proof: multi-page batches, partial exceptions, crashes, races, finalization, idempotent retries, exact compensation, and stale undo rows.

U5 · Depends on U1, U2, and U4

Deliver the focused Cost overlay workspace

Add a run-addressed full-admin route with disambiguated source samples, explicit unit-cost acknowledgment, cost comparison, a prepared impact review before apply, run-wide decisions, terminal abandonment or decision reopening, progress, exceptions, retry, and best-effort run-level undo. Reuse the existing action blocker, responsive review layout, and accessibility semantics.

Proof: access redaction, direct/active-run re-entry, draft reselection, keyboard/focus/progress behavior, cross-page selection, financial-impact and compensability summaries, and existing review regression coverage.

Risk treatment

RiskPlan response
Queued apply races undoEvery worker checks a monotonic run epoch and direction before writes.
Undo loses a mixed cost basisFreeze and restore the exact basis rather than recomputing it from a display cost.
Duplicate source rows disagreeCoalesce identical costs and block conflicting costs before confirmation.
Manager APIs expose costSeparate full-admin queries and commands with negative access tests.
Later finalization drops costPreserve explicit provisional overlay provenance and integrate both finalizers.
Large run exceeds Convex limitsRead chunks individually in a capped Node action, then use normal internal queries/mutations, per-row documents, cursor-bounded writes/preparation, measured apply caps, and internal continuation.
Valid but wrong source column is selectedRequire exact-column acknowledgment and show aggregate plus largest-SKU valuation changes before sealing.
Normal activity makes undo stalePreview currently compensable/stale counts and restore only rows that still match at write time.

Verification strategy

  • Characterize existing parser and review behaviors before extraction.
  • Implement source projection, run contracts, valuation compensation, workers, and UI behavior test-first.
  • Exercise integration seams: exact review → run rows → valuation effect → provisional evidence → later finalization → projection → compensation.
  • Prove negative access for signed-out, manager-elevated, revoked, and cross-store callers.
  • Prove construction, confirmation, apply, and undo convergence after crash/retry, including non-crossing epochs.
  • Prove source acknowledgment, financial-impact summaries, and best-effort undo eligibility are computed from the sealed run.
  • Preserve existing import review, staging, finalization, and direct-write boundary behavior.
