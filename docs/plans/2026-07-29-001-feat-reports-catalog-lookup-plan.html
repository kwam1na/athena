Add catalog lookup to Reports

Reuse Athena's generic SKU search and existing Reports drill-down so administrators can find any catalog variant by product name, SKU, or barcode without scanning period activity.

Scope

The lookup appears at the top of Overview and Items, groups variants beneath their product, and opens the existing SKU detail with the selected reporting period. Origin navigation restores the tab and durable period state while transient search state clears.

Deliberate boundary: this is navigation, not report filtering. It does not change metrics, materialization, freshness, the generic search backend, or the existing detail contract.

Acceptance focus

  • Product name, SKU, and barcode all reach the correct variant.
  • Exact SKU and barcode matches retain backend precedence.
  • Archived, inactive, and no-activity catalog variants remain selectable.
  • Overview and Items periods become inclusive detail ranges.
  • Back restores the originating route context with an empty lookup.

The route owns durable period state. The lookup owns only transient input and result presentation.

Key decisions

DecisionWhy
Reuse generic SKU search unchangedIt already supplies store-scoped identity, exact ranking, and catalog-wide discovery.
Mount one component in both index routesIt stays visually beneath the shared Reports navigation while receiving route-specific period context.
Put Overview window in URL statePeriod and origin navigation become durable without persisting lookup text.
Use a pure period-to-range helperThe existing detail route already consumes inclusive dates; no report contract change is needed.
Preserve backend orderingClient grouping must not undo exact SKU and barcode precedence.
Keep lookup transient and briefly debouncedReduces query churn while keeping navigation URLs focused on durable report context.

Implementation units

U1 · Normalize Reports period context

Add validated Overview window state and pure inclusive-range helpers for Overview and Items period modes.

Primary files: reportPeriodKeys.ts, Overview route/view, and focused route/helper tests.

Proof: Today, week-to-date, trailing 30, day, ISO week, calendar month, year boundary, and leap-year cases resolve correctly.

U2 · Build the shared catalog lookup

Create the accessible lookup UI, call generic SKU search after a short debounce, group through existing adapters, and preserve backend rank.

Primary files: new ReportsCatalogLookup.tsx and its focused component test.

Proof: grouped variants, exact ranking, optional metadata, lifecycle states, loading, empty, truncated, store-change, and keyboard cases.

U3 · Integrate navigation on Overview and Items

Mount the lookup in both index routes and navigate to existing SKU detail with inclusive dates and encoded origin.

Primary files: Overview/Items routes and their focused tests, plus existing detail contract tests.

Proof: both entry points preserve period context; no-activity variants open; back restores the source tab while lookup state clears.

Risks and mitigations

RiskMitigation
Operating-day driftAnchor Overview to its loaded trend date and test date-label arithmetic.
Client reordering breaks exact matchesDisable secondary relevance filtering and assert grouped rank order.
Stale lookup returns after detailMount only in index routes and clear on selection/store change.
Inactive SKU becomes ineligibleKeep lifecycle metadata presentational and test selection.
Origin loses report stateUse the existing encoded-origin contract and test complete round trips.
