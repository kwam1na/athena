Athena · Implementation plan · 2026-08-01

Trustworthy prior-period comparisons in Reports

Extend Athena's server-shaped Reports read models so overview, item-period, and SKU-detail metrics compare against the immediately preceding equivalent period. Preserve bounded Convex reads, missing-data semantics, source evidence, and restrained operator-facing transitions.

Requirements

  • Expose preceding equivalent windows for overview, item-period, and SKU-detail metrics.
  • Respect fixed day/week spans, calendar-month boundaries, and equal-length custom ranges.
  • Keep missing values distinct from legitimate zero baselines.
  • Use indexed, bounded Convex reads and prove limits in tests.
  • Share comparison presentation behavior without redesigning unrelated surfaces.

Implementation units

1. Overview snapshots

Extend shared contracts, derived schema, and overview projection with current/prior rolling snapshots plus bounded legacy-document enrichment.

2. Item and SKU query totals

Resolve prior ranges by period meaning and return explicit prior totals from the canonical report queries.

3. Metric presentation

Consume server-provided comparisons through one shared crossfade and consistent operational copy.

4. Adjacent layout contracts

Preserve predictable table, transaction, and catalog-lookup sizing under the expanded metric content.

5. Validation and generated artifacts

Run focused Vitest suites, rebuild Graphify after final code edits, and finish with bun run pr:athena.
