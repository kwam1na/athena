Cross-agent delivery rails and portable skills

Created 2026-08-27 Type: feat Status: active Review: unanimous Source: canonical Markdown plan

Productize Athena's reusable delivery workflows as a safe, cloneable agent-skills distribution. Prove that tracker-neutral core first. Only then add the smallest neutral provider contract needed to connect independently released skills and enforcement products.

Primary product gate: no rails implementation work begins until the packed portable core beats a no-skill control and a non-Athena maintainer completes an unaided install, delivery task, update, and rollback.

Included

  • Focused planning, execution, review, and compounding workflows.
  • Transactional install, update, rollback, and owned-only removal.
  • One canonical body exposed to Codex and Claude Code.
  • A tracker-neutral core contract with an MCP-first Linear adapter and an optional delivery-rails provider profile.
  • Athena adoption through a local policy overlay, canary, and reversible batches.

Deliberately deferred

  • A third rails product, service, repository, or release train.
  • A permanent cross-product support matrix or self-dogfood gate.
  • Remote transports, signed attestations, hosted control plane, and fleet rollout.
  • Hosts beyond Codex and Claude; trackers beyond Linear; direct tracker API/SDK transports.
  • Automated force-release or TTL reclaimer for provider claims.

Safety boundaries

Repository lifecycle

  • Verify publisher-declared SHA-256 before parsing or extraction.
  • Stream one archive format under entry, size, depth, ratio, and time quotas.
  • Keep active and one prior content-addressed generation.
  • Use a phased git-private journal; marker-committed is the success boundary.
  • Mutate only from explicit maintainer context; fixed roots plus ownership marker and digest govern deletion.
  • Reconcile Git-driven external transitions without hidden hooks.

Provider run

  • Persist the client key before begin; only that key can resume.
  • Publish a complete claim through fsynced temp plus atomic no-replace hard-link.
  • Different or lost keys block without returning a sink or context secret.
  • Allow one active allocation per provider/workspace/candidate with byte/count quotas.
  • Delete terminal roots synchronously; defer force release and TTL reclamation.
  • Persist only redacted, allowlisted, bounded evidence under owner-only roots.

Key risks and mitigations

RiskMitigation
Portable workflows do not improve deliveryCore-first no-skill scorecard and external pilot; stop rails expansion on failure.
Installer damages adopter stateAuthenticated bounded archive, immutable generations, journal, ownership checks, dirty-tree fixtures, rollback.
Rails become a third productHarness-packaged neutral bytes only; extract governance after a second real product demands it.
Qualification becomes stale or self-invalidatingLane digests, whole-archive provenance, immutable snapshots where possible, qualified_at and maximum age.
Candidate-controlled transport executes codeHost-native three-operation adapter; no repository-declared executable, argv, or ambient credentials.
Provider key is lostOwner-only pre-begin persistence; fail closed without sink exposure; defer recovery machinery until observed need.
Athena loses policy during deduplicationPolicy-backed baseline, overlay ownership, canary, rollback rehearsal, reversible batches, existing merge-ready gate.
