Problem and invariants

The backend has roughly 245,000 non-generated lines, 199 tables, 617 admitted operations, and multiple 3,000–6,000-line high-churn orchestration files. The expensive complexity clusters around invisible provider intermediate state, duplicate lifecycle authority, open payload/retention contracts, resource-growth uncertainty, and overly broad facades.

Preserve: one Convex transaction per business action, direct *WithCtx domain composition, inventory-ledger authority, append-only reporting facts, in-transaction approval proof consumption, complete fail-closed operation admission, and stable registered paths.
Do not: split into services, turn outboxes into an internal event bus, build a universal provider reducer, move registered functions during extraction, or remove compatibility seams without measured evidence and a separately tracked contraction.

Operations and security

  • Provider evidence is authenticated before persistence or application; client fields are correlation hints until server-to-provider verification succeeds.
  • Refund request IDs are cryptographically unpredictable, scoped to organization/store/order, never bearer authority, and re-authorized on every create/status/resume/cancel path.
  • WhatsApp callbacks use explicit parent/chunk tables, a durable customer-messaging deletion-fence generation, monotone reduction, and acknowledgement only after every child is applied, duplicate, quarantined, or deletion-terminal.
  • Paystack/reward/refund and MTN exceptions, ambiguous messages, notification/intelligence cleanup poison, POS conflicts, and catalog conflicts all have a named workflow, role, proof posture, SLO, metrics, and capacity fallback.
  • Auth-link and intelligence-owner ambiguity uses deployment dual control and blocks cutover; no broad in-product resolver is introduced.

Verification and rollout

  • Correctness behavior is test-first; fragile extraction and migrations are characterization-first; derived docs/artifacts use sensor-only closure.
  • Each code-bearing unit runs focused tests plus changed Convex lint/audit, webapp typecheck, Graphify rebuild/check, and merge-ready bun run pr:athena. Ingress and script units add admission and harness checks.
  • Provider flows cover duplicate/conflict, reversed order, wrong scope, accepted-plus-timeout, local-commit-plus-lost-response, retention/deletion races, poison work, and reconciliation.
  • Migrations cover preview, bounded resumable apply, overlap delta, collision/quarantine, cutover, observation, and forward-safe recovery.
  • Each hotspot repeats the same representative maintenance change after extraction, must regress on no dimension and improve at least one, and records keep/revert/redirect before follow-on expansion.
  • Six reviewer lenses—coherence, feasibility, product, security, scope, and adversarial—returned unanimous empty findings on the settled Markdown revision.
