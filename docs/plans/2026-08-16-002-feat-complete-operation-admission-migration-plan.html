Assumptions (headless)

User direction: best long-term solution, no legacy behavior. Agent bets below.
  • Scope = every ingress: public mutations/queries/actions + all Hono routes; internal functions stay behind those boundaries.
  • storefront_customer actor kind (http kinds only) resolved from the claimed cookie id with assurance: "bearer_id"; store derived from the claim row, terminal on invalid/missing claim, no trust beyond id possession; customer write routes require origin_allowlist ingress verification (absent/null/unlisted Origin denies; platform/storefrontOrigins.ts) and exclude public; CORS becomes that fixed allowlist; ownership assertions established in owning B1 units from the U1 caller table, route inventory signed off by U10/U11. Session-proof upgrade tracked as a Linear follow-up.
  • Storefront public functions whose only callers are routes become internal; the route is the admitted boundary.
  • Shared-demo reach is policy-owned (capability grant set + new read-intent grant set) enforced by adapters regardless of definitions.
  • Action/HTTP admission is “admitted and started” in its own transaction; such definitions cannot declare store_write readiness; downstream demo writes go through admitted or readiness-checked functions with the admitted store id.
  • Gate obligations (solution note w/ discovery link, v2 landed report, telemetry) are satisfied in U12. Principal minting (convex/auth.ts) is the trust root outside the rail, named in FRAMEWORK_ENTRY_POINTS.

Key technical decisions

  • Composition root outside the rail core; createAdmissionRail({adapters, resourceGuards, capture}); allowlist import lint.
  • Chain shared demo → normal user → storefront customer → public; outcomes admitted/denied/unauthenticated/not_applicable; fall through only on unauthenticated/not_applicable; identity before scope; no message sniffing.
  • storefront_customer: http kinds only, store derived from claim row, terminal denial (incl. storeless guests → backfill), bearer assurance, ownership assertions established per inventory.
  • Set-valued dynamic capability (pos sync) with user_error denial contract.
  • Bound target guards (scope / arg / resolver) evaluated for all actors and kinds after scope, mapped site-by-site.
  • Typed read-intent catalog + grant set fixed in U1; definitions are the only capability/gateway source with both-direction static invariants.
  • Action/HTTP semantics (store_ready fence; http_read via internal query); admitted bodies call only internal.* per the U1-generated caller table.
  • Checker: no exemptions, honest framework entry points, --path, --partition, cwd-independent, bare invocation in audit:convex.
  • U1 (U1a → U1b ∥ U1c) pre-creates per-unit domain modules, closes catalogs, seeds grants, owns http/utils.ts, runs codegen; strict file ownership; single-writer codegen; Phase B in two waves (B1 Convex modules → B2 routes).
