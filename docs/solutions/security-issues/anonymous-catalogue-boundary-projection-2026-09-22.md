# Anonymous catalogue routes need a drop-only boundary projection, not a document spread

## Problem

The five anonymous catalogue responses were built by spreading Convex documents
(`{ ...product }`, `{ ...sku }`) and adding enrichment on top. Every column the
operator added to `productSchema` or `productSkuSchema` therefore reached the
public internet by default: cost prices, net prices, barcodes, on-hand and
reserved stock, the creating user's id and the organization id. Nothing in the
type system or the tests noticed, because the leak is the *absence* of a step.

## Symptoms

- Anonymous `GET /products`, `/products/:productId`, `/products/bestSellers`,
  `/products/featured` returned `unitCost`, `netPrice`, `barcode`,
  `barcodeAutoGenerated`, `inventoryCount`, `reservedQuantity`,
  `durableQuantityAvailable`, `createdByUserId`, `organizationId`,
  `posVisible`, `pesewasMigratedAt`, `areProcessingFeesAbsorbed`.
- `productSku.retrieve` nests a whole `product` document inside the best-seller
  rows, so the same fields leaked a second time through a different path.
- `GET /homepage-snapshot` carried `netPriceAmountMinor`, which the storefront
  mapped into a field nothing ever read.

## What Didn't Work

- Projecting inside the cached action (`inventory/productUtil.getAllProducts`)
  would have left already-cached Valkey entries unprojected until eviction, and
  a cache hit would not have been covered by the route's own tests.
- A recursive "drop these key names anywhere" walker was rejected: `category`
  and `store` documents legitimately carry `organizationId`, and the storefront
  reads `store.organizationId`. Name-based recursion turns a bounded projection
  into an unbounded behaviour change.

## Solution

`convex/storeFront/publicCatalog.ts` holds the `public_catalog.v1` projection:
four shape-aware functions (list, detail, best sellers, featured) that keep
existing field names and remove only an enumerated drop set, including the
`reservedQuantity` / `durableQuantityAvailable` counters the availability
adjustment attaches at read time, and the `product` document nested under a
best-seller SKU. The route handlers in `http/domains/core/routes/products.ts`
apply it **after** the query or cached-action read, so a cache hit is projected
exactly like a miss.

The decision is enumerated rather than implied. `publicCatalog.ts` exports a
kept list and a dropped list per schema, and `publicCatalog.test.ts` asserts
that `Object.keys(productSchema.fields)` and `Object.keys(productSkuSchema.fields)`
equal the union of the two lists. Adding a column without deciding fails the
test rather than shipping it.

`@athena/contracts` gained `PublicCatalogProduct` / `PublicCatalogSku` as
`Omit<...>` of the document types, and the storefront switched its catalogue
imports to them, so the type the storefront programs against is now the type
the wire actually carries.

## Why This Works

The leak was structural, not a single missing field: a spread inherits every
future column. Moving the decision into an enumerated list at the boundary
makes "what does an anonymous caller see" a reviewable artefact, and makes the
schema-enumeration test the thing that notices the next column. Placing the
projection at the route rather than in the read keeps the operator app's own
use of the same internal queries unchanged.

## Prevention

- Do not answer an anonymous HTTP route with a document spread. Project at the
  boundary, drop-only, in a module the route imports.
- Enumerate the schema. A test that compares the schema's keys against
  keep ∪ drop converts "someone forgot" into a red test.
- Project after the cache, never inside it; then test a cache hit and a miss
  through the same handler.
- Characterize the consumer before dropping a field. `inventoryCount` looked
  load-bearing until a read-set sweep of `packages/storefront-webapp` showed the
  storefront gets counts from `POST /storefront/inventory/batch` and that
  `src/lib/schemas/product.ts` (which names `unitCost` and `inventoryCount`) is
  imported by nothing.
- Follow the nesting. `productSku.retrieve` re-attaches a product document, so
  a per-entity projection has to recurse into the shapes it actually produces.
