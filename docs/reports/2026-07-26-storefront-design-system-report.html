Executive Summary

This delivery turns the storefront's partial Tailwind and copied component inventory into an explicit, package-local design system. It establishes a light-first semantic foundation, accessible primitives, shared page and state patterns, one Storybook workbench, and automated policy checks, then migrates the planned representative customer-journey surfaces onto those contracts.

The finish line is an open, mergeable, CI-green pull request. It is not merged, deployed, or aligned back to local main in this report.

Why It Mattered

Before this work, CSS variables, raw palette utilities, arbitrary geometry, copied dashboard components, route-local containers, blank loading branches, and several overlay implementations all competed as UI authorities. That made visual consistency difficult and allowed accessibility behavior to vary by route.

The refactor also fixes global safety gaps: browser zoom is restored, focus treatment is visible, loading controls are truly unavailable, overlays have a shared focus contract, and motion has a reduced-motion path.

Mental Model

Think of the storefront as a one-way stack. Doctrine explains the customer-facing intent. Semantic tokens name that intent. Accessible primitives implement interaction. Patterns compose pages and states. Routes supply commerce data and behavior. Storybook and policy tests inspect every layer. Athena supplied the governance model and conformance expectations—not its operator-specific values, density, shell, or components.

The dependency direction matters: foundations and primitives do not import products, checkout state, routes, analytics, or API clients. Commerce behavior remains above the design-system boundary.

Doctrine → Tokens → Primitives → Patterns → Templates/Routes
                         ↘ Storybook + policy enforcement

Before and After

  • Before: 57 top-level UI files mixed supported primitives, feature code, dashboard copies, and dead inventory. After: a machine-readable catalog classifies every remaining non-test UI file and dependency tests protect primitive neutrality.
  • Before: the 1024px container, state screens, form geometry, overlays, and motion were repeated locally. After: StorefrontPage, PageState, semantic control recipes, and Radix-backed overlays own those contracts.
  • Before: incomplete dark-mode declarations implied unsupported behavior. After: the system is explicitly light-first and theme-ready without claiming a dark launch.
  • Before: there was no active component workbench or changed-file visual policy. After: Storybook is organized into Guidance, Foundations, Primitives, Patterns, and Templates with a11y enforcement and raw-value guardrails.
  • Cleanup removed proven zero-consumer components, obsolete modal families, dashboard state copies, and unused Martel font assets. Live legacy accent aliases remain temporarily because consumers still exist; policy blocks new use.

Journey Migration

  • Shell: declarative route state now owns navigation visibility, overlays, focus restoration, and scroll locking.
  • Catalog and product: cards, filters, gallery, variants, inventory, reviews, and responsive actions use semantic tokens and shared controls.
  • Bag and checkout: storage schemas, pricing, payment gates, redirects, idempotency, and telemetry stay intact while page, form, loading, retry, and terminal presentation normalize.
  • Account and post-purchase: representative auth, order, rewards, review, receipt, policy, and maintenance surfaces retain their domain boundaries and gain normalized customer-facing states.
  • Storybook and retained browser artifacts use synthetic fixtures under a documented redaction and lifecycle policy.

Failure and Security Boundaries

This is a presentation and accessibility normalization, not a commerce rewrite. TanStack route paths, params, search contracts, generated routing, checkout serialization, API behavior, payment providers, fulfillment and currency calculations, object ownership, auth redirects, and journey telemetry remain feature-owned.

Invalid receipts stay isolated, unauthenticated account entry still redirects, loading and recoverable failures now render named states, and overlay teardown restores focus and body scroll. Synthetic data is required for stories and retained evidence.

How to Extend the System

  • Start in the design doctrine and machine-readable catalog before adding a variant.
  • Use semantic tokens; do not add raw status colors, hex values, arbitrary Tailwind geometry, or legacy accent aliases.
  • Prefer an existing primitive or pattern. New primitives must remain free of route, feature, API, query, analytics, and context dependencies.
  • Add the state to Storybook and a focused interaction or accessibility test, then run the changed-file policy.
  • For route work, preserve existing search, selectors, persistence, auth, telemetry, and payment behavior unless a separate product ticket authorizes change.
