Executive summary

This candidate adds a human documentation-waiver path that CI can verify without trusting an agent-controlled terminal. It also adds Daily Close reporting for successfully applied owed-close recovery, clarifies POS local-data health, and adds source-backed architecture diagrams.

The waiver request is not approval. A distinct authorized reviewer must approve a protected GitHub Environment; CI then verifies the immutable artifact, workflow provenance, approval history, exact PR-head identity, base, merge base, and live findings.

Problem and context

The documentation gate had no durable exception path, while a prompt or PTY could not prove human intent. Historic owed closes could complete without the daily manager report intent, stale close reports displayed an ambiguous time, and terminal storage guidance mixed browser quota with retained ledger pressure.

This first waiver-workflow PR must bootstrap through ordinary documentation because the trusted workflow does not exist on the default branch until merge.

Mental model

Think of the command as an application and the GitHub Environment review as the signature. The artifact is the signed envelope, and its candidate fields are the address. CI accepts the envelope only when GitHub confirms the signer, workflow, address, and covered findings.

Operational changes follow the same authority rule: the owed-close sweep requests reporting, the close function emits only after a newly completed apply, and the notification rail remains the delivery authority.

Before and after

  • Before: documentation findings always blocked CI; after: only the two registered documentation policies may be waived by a protected, candidate-bound attestation.
  • Before: dispatcher identity was at risk of being mistaken for approval; after: requestedBy and approvedBy are distinct and CI re-fetches environment review history.
  • Before: historic catch-up completion was silent; after: successful apply emits the idempotent daily-manager-report intent.
  • Before: completion time hid cross-date context; after: stale-day completion includes month and day in store time.
  • Before: terminal health used generic storage language; after: browser quota, ledger maintenance, persistence, counts, and cleanup guidance are separate.

What changed and what did not

Review and telemetry obligations remain non-waivable. Live-current documentation still passes without GitHub access. Required CI still validates GitHub's synthetic merge commit; only waiver identity is recomputed from the immutable PR head.

Store health measurements and severity remain unchanged; the UI presentation is clearer. Dry runs and non-completed historic close outcomes remain silent. Storefront and Valkey runtime behavior are untouched.

Failure boundaries

  • Missing approval history, self-approval, unauthorized reviewer, wrong workflow, non-green run, forged check payload, stale head/base/merge base, changed deliverable, or uncovered finding fails closed.
  • The success check is created only after the attestation artifact uploads, avoiding a check-before-artifact race.
  • The protected environment is external repository configuration and must have required reviewers plus self-review prevention before the path is relied upon.
  • The workflow must already be present on main, so this bootstrap PR uses normal documentation artifacts.

Next-time guidance

  • Do not treat PTY interactivity, a local prompt, or the workflow dispatcher as human approval.
  • Prepare and push a clean candidate before requesting a waiver; any head or base movement requires a new request.
  • Keep merge-candidate CI intact and derive PR-head waiver identity separately with Git plumbing.
  • After merge, deploy only the Convex and Athena admin surfaces selected by the merged diff, then verify both production paths.
