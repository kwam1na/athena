Executive summary

This branch turns the Daily Operations agent from a 78%-commit, 43-second, jargon-heavy responder into a 100%-commit, ~13-second responder that speaks the product's language. Every change was driven by a measured loop: a 20-question regression set run live against the dev deployment after each change, with server-truth trace analysis deciding what shipped. Two chapters: turn-loop and latency gap closures (stop at the commit, forced completion, ref snapping, catalog embedding, discover-tool removal, gpt-5-mini at low reasoning effort, a host-authored first progress beat) and mechanical product-tone enforcement (a typed product lexicon, money display annotation that fixed a 100× unit misread, a tone sensor with a one-denial bound, and deterministic narrative normalization at commit).

Headline numbers, all from digest-guarded live phases (the driver asserts the deployment digest at preflight and after every turn, so a concurrent deploy aborts the phase instead of contaminating it) on the data-rich operating day: commit rate 21/27 (pre-fix corpus) to 20/20 on every final phase; inner-call denials 38% to 0%; whole-turn median 43.1 s to 12.8 s; committed-prose jargon 8.0 to 0.5 tokens per 1,000 characters; reasoning tokens roughly 12× lower (116k across the set at baseline, 9.5k on the final phase).

Problem and context

A sweep of every traced production turn found three defect classes explaining nearly all loss: answers written as prose but never committed through athena.completeRun (the model treated its narration as the answer); first reads denied because the prompt handed the model a raw storeRef that the validator forbids in arguments; and invented result fields narrated as "could not be read". Later loops surfaced more of the same shape: transcribed refs rejected for a dropped prefix, an empty-run deadlock, guessed namespaces and enum values, a discover-first habit costing a full round trip every turn, and operator-facing prose full of backend vocabulary — including money figures inflated 100× because results carried minor units with no unit disclosure.

The common cause, proven repeatedly by measurement: the harness knew something and did not disclose it, then punished the model for not knowing it.

Mental model

Think of the harness as three concentric rings around the model. The input ring decides what the model is shown: the grant catalog with call signatures, field names and labels, enum values, and money values that carry their product display string. The protocol ring decides what a call may do: the five fixed tools, budgets, citations, and denials that name the exact fix. The output ring decides what the operator sees: a tone sensor, deterministic normalization of internal tokens, and the committed artifact as the only released answer.

The branch's one-line thesis is that fixes belong as far inward as possible: shaping the input beats policing the output. Instructions failed twice (the discover habit and the model-authored "Sources:" footer both survived explicit instructions); mechanism succeeded both times (removing the tool from the provider offer, stripping the footer at commit). Enforcement without disclosure made prose measurably worse; disclosure made enforcement nearly unnecessary.

Before and after

Turn loop

Before: the model narrated an answer, sometimes never calling completeRun; the loop ran to its step budget; first reads guessed arguments and were denied; every turn began with a redundant discover call; reasoning ran at default effort with a silent opening gap. After: the stream stops the moment the terminal tool settles; a prose ending gets a forced tool-choice continuation with one corrective retry; the prompt embeds the grant catalog (signatures, fields, enum values) so discover is no longer offered to the provider; the profile pins gpt-5-mini at low reasoning effort; the host authors a checking_sources milestone the instant the runtime turn starts.

Operator-facing prose

Before: operations.storeDay: lifecycleStage = close_blocked; registerBlockerCount = 1, "GHS 1,414,900" for GH₵14,149, refs pasted into a homemade sources footer. After: money values arrive annotated (display: "GH₵14,149"), the catalog teaches operator wording (grossRevenue (say: revenue), close_blocked → close blocked), a sensor holds the narrative to the run's own evidence with at most one corrective denial, and the kernel normalizes residual internal tokens at commit under two safety rules — structure-preserving substitutions only, and platform-known tokens only.

Failure and trust boundaries

Two boundaries deliberately moved, both narrow. First, the provider-visible tool list may now differ from the kernel ledger: when the prompt embeds the catalog, athena.discover is not offered to the model, but the kernel keeps all five tools for dispatch ledger, replay, and fake-adapter parity. Second, the kernel now edits the committed narrative — bounded to a trailing sources footer stripped only when every non-empty line in it carries a ref token (a prose-bearing footer stays verbatim; the surface renders citations itself), and structure-preserving substitution of platform-known internal tokens. Free prose is never pattern-matched, the model's submitted text remains in the dispatch ledger unmodified, and the provisional narrative stream is untouched.

What still fails and how: a stub narrative earns exactly one corrective denial naming the fix, then the retry commits regardless (no loops). Unknown internal tokens (for example workflow step ids) pass through and surface in turn_report.tone telemetry; each becomes a one-line lexicon entry, so the floor ratchets rather than rots.

What changed, and what did not

Changed

  • Turn loop: stop at the terminal-tool settle; forced completion continuation; one corrective retry; 60 s elapsed headroom.
  • Disclosure: catalog in the prompt (signatures, fields with operator labels, enum values and wording, money display contract); granted read paths in facade rejections; field advisories on misread fields.
  • Ref handling: content-hash tail resolution with unique-containment tolerance; refusals name the valid refs verbatim; honest no_usable_sources with zero attempts.
  • Model: gpt-5-mini pinned in the profile at low reasoning effort; host-authored first milestone.
  • Tone: lexicon, money display annotation, tone sensor (enforce by default, one denial, ATHENA_AGENT_TONE_POLICY=warn downgrade), narrative normalization, sources-footer strip, per-profile overlays, tone telemetry on turn_report.

Intentionally unchanged

  • The kernel's fixed five-tool catalog, dispatch ledger fingerprinting, and replay semantics.
  • The answer surface and its renderer: provisional text is still never persisted, the committed artifact is still the only released answer, and the UI never rewrites model prose.
  • Citation, egress-class, and budget semantics; the completion outbox; grant authority rules.
  • Currency conventions: display formatting reuses the app's own currencyFormatter and per-value currency codes; the repo-wide minor-units convention is inherited, not reinvented.

Next time

  • When a model output violates a convention, first ask what the harness knew and did not disclose. Instructions are the weakest ring; measure before crediting them.
  • Isolate an enforcement mechanism's contribution (labels+warn vs labels+enforce) before adopting it; enforcement without disclosure measured negative here.
  • Guard live measurement phases with a deployment-digest check, use fresh idempotency keys per phase, and pin the operating date — three separate confounds corrupted one benchmark each this delivery.
  • Measure committed operator-visible text, not model-submitted text, once any commit-time normalization exists.
  • Never silently fall back on an authorization refusal: an empty catalog shipped that way once, and only prompt-content verification caught it.

Comprehension quiz

  1. Why were the agent's money figures inflated 100× before this branch?

    1. The reports pipeline double-counted refunds.
    2. Capability results carried minor-unit amounts with no unit disclosure, so the model read pesewas as cedis.
    3. The currency formatter used the wrong locale.
    4. The model hallucinated totals when reads were partial.

    Results served values like { amount: 1414900, currency: "GHS" } with the Minor suffix stripped; the only reasonable reading was cedis. The fix annotates every money value with its product display string at the boundary.

  2. What finally stopped the model from calling athena.discover at the start of every turn?

    1. A stronger instruction telling it not to call discover.
    2. A budget that made discover calls expensive.
    3. Embedding the grant catalog in the prompt and removing discover from the provider-visible tool list.
    4. Caching discover results between turns.

    Instructions — including an explicit "do NOT" — changed nothing across 20/20 turns. Removing the tool from the offer while the kernel ledger keeps all five tools ended the habit deterministically.

  3. Enforcement without vocabulary disclosure made prose worse. What is the mechanism?

    1. The model was denied and told to rewrite without being shown the operator wording, so it produced longer, more defensive prose with the same tokens.
    2. The denial consumed the token budget needed for a good answer.
    3. The retry used a different, weaker model.
    4. The sensor's false positives punished correct answers.

    The isolation phases showed it directly: enforce-without-labels raised jargon density to 10.9/1k with a 73 s p90 tail, while labels alone cut it to 7.8 for free — the words have to be shown before compliance is possible.

  4. Which two safety rules bound the kernel's narrative normalization?

    1. Maximum edit distance and a profanity filter.
    2. Structure-preserving substitutions only, and platform-known tokens only.
    3. Rewrite only below a confidence threshold, and only in warn mode.
    4. Rewrite only the first paragraph, and never inside quotes.

    Humanizing a token in place ("lifecycleStage" → "lifecycle stage") keeps the sentence parsing; free-form labels would garble grammar and stay in disclosure and denial fixes. And only tokens the run served or the lexicon names are ever touched — free prose is never pattern-matched.

  5. What does the tone sensor's enforce mode guarantee about retries?

    1. It retries until the narrative is clean.
    2. It spends exactly one corrective denial naming the fixes; the retry commits even if still imperfect.
    3. It falls back to warn mode after three denials.
    4. It cancels the turn if the retry still has findings.

    The bound protects latency: a denial loop would hand back the branch's 2-3× latency win. Residual findings ride turn_report telemetry instead of blocking the answer.

  6. Why is the committed narrative, not the model-submitted text, the right thing to measure after this branch?

    1. The submitted text is truncated in traces.
    2. Normalization runs at commit, so the operator-visible artifact deliberately differs from what the model wrote.
    3. The submitted text includes reasoning tokens.
    4. They are identical; either works.

    The final phase measured 3.6/1k jargon in submitted text but 0.5/1k in the committed artifact — the difference is the normalization working as designed.

  7. How does completeRun resolve a citation ref the model transcribed imperfectly?

    1. It fuzzy-matches on edit distance across all known refs.
    2. It rejects immediately and ends the run.
    3. It resolves by the content-hash tail — exact match first, then unique containment — against refs this run itself minted.
    4. It asks the model to re-read the source.

    Refs are opaque handles the turn handed out; the 32-hex content tail identifies the intended handle exactly, and nothing is granted that the run's reads did not already return.

  8. During delivery, one live benchmark phase produced numbers identical to a contaminated run. Why?

    1. The dev deployment was still running the foreign code.
    2. Reusing the phase tag reused the turn idempotency keys, so the harness returned the prior bindings instead of executing new turns.
    3. The trace exporter cached old files.
    4. The question set was accidentally frozen.

    The deployment digest was verified correct throughout that phase, ruling out foreign code; startOperatorTurn dedupes on the idempotency key, which embeds the phase tag, so the "new" run replayed old bindings with ~10 s completions. Fresh tags per attempt are now mandatory, and the driver also aborts on any deployment-digest mismatch.

  9. What happens to the model's own trailing "Sources:" footer, and why is that acceptable?

    1. It is rewritten into operator wording.
    2. It is left as written; citations are the model's responsibility.
    3. A trailing footer whose every line is just refs is stripped at commit, because the answer surface renders the committed citations under "Sources" itself.
    4. It causes a denial until removed.

    The footer duplicates the UI in the wrong vocabulary, and neither disclosure nor a corrective denial stopped the habit. The strip is conservative: a footer carrying real prose, or a sources mention mid-answer, stays verbatim.

  10. Why does the catalog embedded in the prompt come from the viewer-authority projection rather than dispatch reauthorization?

    1. The projection is cheaper to compute.
    2. Dispatch-purpose reauthorization always refuses before the run is marked running, and a silent fallback once shipped an empty catalog.
    3. The projection includes projection-gated fields.
    4. Dispatch reauthorization requires a network call.

    The first "catalog embedded" build ate that refusal with a fallback and silently sent no catalog — the phases credited to it were actually the enum disclosure working. The fix sources the catalog from the viewer-authority projection — the grant snapshot the prepare rung already holds, and the lesson is to never silently fall back on an authorization refusal.
