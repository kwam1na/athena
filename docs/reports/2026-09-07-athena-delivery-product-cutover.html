What changes

Athena delegates candidate preparation, saved delivery context, evidence admission, gate decisions, records and run accounting to the installed delivery product. Repository policy still selects the required sensors, reviewers, reports and finish line.

The executable release contains the workflow and runtime needed by an adopter. Installing it no longer requires either producer checkout.

Why this work exists

Athena and the portable harness maintained overlapping delivery mechanics. That duplication made it possible for local checks, transported evidence and CI to disagree about which candidate had been approved.

A release also needed to work as an artifact in an ordinary adopter repository, with real Claude and Codex sessions retaining their native tools and permissions.

Who owns each decision

  • The installed product owns common delivery state and admission decisions.
  • Athena owns policy, sensor selection, reviewer selection, report conventions and deployment requirements.
  • Claude and Codex own their native sessions, tools, credentials and worktrees. A review issuer label does not authenticate a host.
  • Run events describe activity. Gate evidence and its current candidate binding authorize admission.

Before and after

Previously, Athena wrappers carried their own candidate, obligation, context and accounting behavior. After this cutover, familiar commands call the installed product and provide Athena-specific facts.

Previously, a transported telemetry export could depend on a staged Git tree that did not exist in the receiving clone. The new export records a strict validation digest; verification compares that digest with the current projection without requiring the old tree object.

How to operate it

  • Install the approved executable archive and metadata through agent-skills:install; inspect delivery:status for current lifecycle, product readiness and blockers.
  • Use the repository entry points and installed product to prepare, review, admit evidence, gate, record and verify. Do not manufacture receipts or relabel historical manifests.
  • Preserve existing saved context before checking freshness with delivery:resume. If context is missing, recover and explicitly save the accepted contract and stage, then retry. Only a current satisfied_evidence resolution for review.green, with the complete required reviewer coverage and no new actionable feedback, supports review reuse; waived, not_applicable, missing or other resolutions do not. Other admission and recovery blockers retain their own force.
  • Reports and solution notes are bundled into the Athena app and normally require a webapp deployment after merge. For this delivery, the user explicitly instructed skipping Athena deployment; no deployment is claimed.
  • Preserve the workflow release bound at the first review round in the closing workflow record. Gate evidence uses the current prepared installation; never relabel earlier rounds after an artifact update.
