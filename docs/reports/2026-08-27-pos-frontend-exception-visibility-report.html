Executive summary

POS frontend failures that previously stopped at console output or local UI feedback now travel through one bounded diagnostic rail into Terminal Health. The change covers all POS child routes, handled infrastructure failures, global runtime failures, route-render failures, local durability, authorized Convex ingestion, 30-day retention, and support-facing inspection.

The envelope is deliberately finite and redacted: it records closed classifications, operations, route IDs, standard error names, sanitized source coordinates, and approved scalar metadata without arbitrary error messages, stacks, customer data, receipt content, credentials, or raw paths.

Problem and constraints

Athena already had pieces of POS telemetry, but ownership and evidence were uneven. Some routes had no host, many handled exceptions never entered the rail, reconnect-time identity could relabel historical events, and unbounded diagnostic text was unsafe to retain remotely.

The implementation had to remain best-effort and local-first: telemetry cannot block checkout, mutate business state, weaken manager authorization, or invent terminal identity when browser coordination or IndexedDB is unavailable.

  • One business action still commits its domain state in one Convex transaction.
  • Client-reported terminal and fingerprint fields remain correlation evidence, not authorization.
  • No production deployment is part of this delivery.

Mental model

Think of the rail as capture → immutable local shard → occurrence witness → scoped drain → authorized Convex row → Terminal Health. Scope is stamped at occurrence time and later enrichment is allowed only when exact route, owner token, terminal generation, transition revision, store seed, and telemetry identity epoch agree.

Terminal or fingerprint changes publish an owner-specific transition lease. Capture fences immediately; only the writer's exact lease may settle. If exact coordination is unavailable, an uncoordinated fence keeps rows pending until authoritative recovery or bounded quiescence.

Before and after

  • Before: child routes could mount without a telemetry owner. After: the POS parent route owns the host and error boundary for every /pos/** surface.
  • Before: handled storage, settings, printing, expense, and drawer failures often ended at logs or toasts. After: approved producers emit finite diagnostic classifications and operation labels.
  • Before: shared-array persistence and reconnect-time context could race. After: immutable per-event shards, exact occurrence bindings, generation leases, epoch witnesses, and scoped acknowledgements preserve historical attribution.
  • Before: support saw limited client context. After: Terminal Health exposes errors and warnings with restrained empty states and terminal detail placement.
  • Before: sustained error volume could accumulate removal fences. After: the live ring is 200 events and removal fences are normally capped at 400, with safety-first retention when artifact deletion fails.

What changed

  • Added v2 shared redaction and vocabulary contracts used by browser and Convex validators.
  • Added route-wide browser capture, handled-exception gateways, runtime counters, immutable shards, tombstones, occurrence bindings, exact IndexedDB witnesses, per-scope backoff, and fair retry scheduling.
  • Added Convex ingestion, deduplication, authorization, same-store terminal validation, queries, schema fields, indexes, and bounded retention continuation.
  • Added Terminal Health filters, detail presentation, support copy, and tests.
  • Updated operational guidance, agent architecture/testing indexes, generated API and route artifacts, and Graphify output.

Operational guidance

  • Use Terminal Health → Client diagnostics to inspect terminal-scoped errors and warnings.
  • Treat terminal/fingerprint attribution as client-reported evidence; authorization remains organization and store based on the server.
  • When adding a producer, choose an existing closed flow, classification, operation, route, and metadata key; do not add free-form messages.
  • When changing terminal seed or fingerprint identity, use the exact lease/uncoordinated transition contract so capture fences before mutation.
  • If storage degradation counters rise, diagnostics remain best-effort and business operations continue; investigate browser storage and IndexedDB separately.
