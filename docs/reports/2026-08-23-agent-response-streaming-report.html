Executive summary

Ask Athena now shows the model thinking out loud while a turn runs. The text is explicitly provisional: it lives in one delete-only table, is written only by the runtime host through a mutation that reauthorizes the operator on every write, is served only by a query that reauthorizes on every read, is replaced by the committed answer at commit, and is deleted on every terminal cause. The committed artifact minted by completeRun is still the only released answer; its transaction is untouched.

Five units landed on one integration branch: the runtime contract gained a narrative_delta event and a protocol bump (U1); the Convex Agent adapter streams text deltas instead of waiting for the whole response (U2); the kernel gained the agentProvisionalNarrative row, the host flush, the previewTurnNarrative ladder, and deletion at every exit (U3); the reusable host renders a client-derived provisionalState with strict focus and live-region rules (U4); the harness docs describe the new exposure rule "Provisional stream, recallable view" (U5). A production-shaped operator turn on the dev deployment showed narration before the first tool call (narrative_delta×7 then tool_call_requested, first delta at 12.5 s, completion at 45.6 s), and no provisional row was left at rest afterwards.

Problem and context

The agent-harness foundation deliberately buffered the model narrative server-side (Key Technical Decision 12) so that release was one reauthorized transaction and revocation could land before anything was recallable. That kept the release gate strong but made the experience poor: a real provider turn showed nothing for ten-plus seconds and then the whole answer. Operators expect to watch an answer form.

The naive fix — persist deltas through the Convex Agent component and subscribe from the browser — would have turned streamed text into an early release: it would reach the durable record and the component's replay context, have no per-read authority check, and have no deletion story. The plan (24 review rounds, eight lenses) settled on treating streamed text as its own exposure class with its own table, markers, flush refusals, preview ladder, and deletion list, and amended the foundation's invariant to: the narrative never enters Athena's durable record, projected history, a citation, or a prompt, and never survives a terminal cause.

Mental model

Think of the provisional narrative as a whiteboard in a room with a guard at the door. The model writes on the whiteboard as it thinks. Only the runtime host holds the marker, and every time it writes it asks the guard (the flush's reauthorization) whether the operator is still allowed in the room. Anyone who wants to read the whiteboard has to pass the same guard again (the preview ladder). When the turn ends — by answer, cancel, failure, revocation, fence, or the host dying — the whiteboard is wiped. The answer itself is never written on the whiteboard; it is handed over separately through completeRun, and the whiteboard is wiped at that moment too.

Two facts survive the wipe, on the turn binding: provisionalReleasedAt (text was readable at some point) and provisionalViewedAt (the client said it painted it). Investigators derive provisionalExposurePresumed and revokedAfterProvisionalExposure from those, never from the text.

Before and after

Before

  • Adapter: agent.generateText; the narrative arrived whole in turn_completed.narrative.
  • Host: forwarded only server-authored milestones (progress) to the binding.
  • Browser: milestone list, then the committed answer.

After (data-flow order)

  1. Provider text-delta parts → adapter coalescer (24 chars / sentence boundary / text-end; always flushed before a tool_call_requested) → narrative_delta { draftOrdinal, text }; finish-step advances the draft ordinal. Reasoning, tool-input, source and file parts are dropped by default.
  2. Host keeps the current draft in memory and pumps one flushProvisionalNarrative at a time; an OCC-failed flush is dropped and the next carries the whole draft; a refused flush stops the chain for the turn. At the completeRun request the host sets a stop flag and drains the flush in flight so the commit transaction is never contended; on a non-success commit outcome it resumes with the next draft.
  3. The flush refuses, in order: policy_buffered, any reauthorizeGrantWithCtx refusal, turn_not_streaming, egress_class_missing, egress_beyond_authority, empty_text; every refusal except the empty-text no-op deletes the row. On success it upserts the row, caps text at 16 KiB on a codepoint boundary, refreshes expiresAt from the server clock, and sets provisionalReleasedAt once.
  4. previewTurnNarrative (never writes): reauthorizeTurnAccess → epoch fence → profile policy → egress rank against the write-once provider-invocation row (the turn's egress class is stamped once by prepareTurn when the invocation row is inserted, and never rewritten; after a release, a missing stamp withdraws) → suppressed/abandoned → run state → expiry. Only the streaming arm carries text; withdrawn carries a closed reason and released.
  5. Client derives provisionalState (disabled > withdrawn > superseded > committing > reset > paused_at_limit > streaming > awaiting_first_text > stalled > none), with a turn-keyed latched verdict, one ttlMs deadline timer, and the expiry guard on every text-bearing arm.
  6. Panel renders the draft inside a labeled "Draft in progress. Not verified." container with its own polite live region, a role="alert" withdrawn notice, one focus effect with a turn-keyed claim latch, and sticky scroll-follow.

Failure boundaries

  • Revoked owner acknowledges — acknowledgeProvisionalView refuses and deletes the row: a view-side revocation cleanup, not a sixth terminal cause.
  • Cancel mid-stream — the lifecycle clamp deletes the row in the cancel transaction; the panel shows "Draft withdrawn. This request was stopped." and focus stays where the operator's Stop put it. Stop before any text shows only "Stopped." — a never-released turn never withdraws.
  • Provider error mid-stream — arrives as a stream error part, terminalizes the turn as failed with provider_failure; no trailing delta; the clamp deletes.
  • Commit succeeds, provider then fails — the committed artifact stands; finalizeTurnWithCtx deletes the row (the later failed transition does not re-clamp).
  • Membership revoked / profile disabled / epoch advanced mid-turn — the next flush refuses and deletes; the preview withdraws immediately with a closed reason; the run is canceled moments later by the existing sweeps.
  • Egress downgrade — the stamped turn class outranks the operator's grant: flush refused and deleted, preview withdrawn / egress_beyond_authority. A mere capability narrowing keeps streaming. After a release, a missing stamp also withdraws (fail-closed parity with the flush).
  • Buffered profile — the flush refuses policy_buffered; the preview reports disabled (milestones only); a post-release policy flip reads withdrawn / policy_disabled.
  • Dead host — the row ages past its 5-minute expiry: the preview reports stalled (no text), the client's own timer drops the text, and the repair sweep deletes it and logs the count.
  • Over 16 KiB — the server truncates at a codepoint boundary and sets truncated; the panel shows the "display limit reached" line; the host keeps flushing idempotently.
  • Panel remount mid-stream — the first painted ordinal is not a reset; a restored non-bottom scroll position is kept; an already-withdrawn turn shows its notice again but moves no focus.
  • Commit succeeds, provider then fails (trail) — the answer stands and so does its trail: the trail is written at commit, not at the end of the drive, so the later failed transition leaves it in place.
  • Operator scrolls while text arrives — a wheel, pointer, touch or navigation key withdraws the follow by intent (never by position, since a smooth scroll in flight is briefly away from the bottom); the floating "Scroll to latest" control restarts it, as does the next question. A draft that ends no longer takes the position back.
  • Reduced motion — the reveal paints whole, no word span is wrapped, the scroll container does not glide, and the preference is read on the first render so no frame runs before it is known.

Comprehension quiz

  1. Which of these is the only released answer after this change?

    1. The last narrative_delta the adapter emitted.
    2. The artifact minted by the completeRun transaction.
    3. The text in the agentProvisionalNarrative row at commit time.
    4. Whatever the panel last painted.

    The provisional text is the model thinking out loud and is replaced, not promoted; completeRun remains the single reauthorized release.

  2. Why does the host stop flushing and drain the flush in flight when it sees the completeRun tool request?

    1. To save Convex write bandwidth.
    2. So the commit transaction is never contended by a streaming write.
    3. Because the preview would otherwise show the committed answer twice.
    4. Because the adapter stops emitting deltas at that point.

    The request is emitted before the tool runs and emit awaits the hook, so stopping there guarantees no flush lands inside the commit.

  3. A turn commits successfully. Which site deletes the provisional row?

    1. The lifecycle clamp, inside the commit transaction.
    2. suppressReleaseWithCtx.
    3. finalizeTurnWithCtx, at the end of the driven turn, outside the commit.
    4. The repair sweep on its next pass.

    The clamp skips completed on purpose so the commit transaction stays untouched; finalize deletes above its already_terminal early return.

  4. The preview's egress rung compares the operator's grant against which value?

    1. The egressClass stored on the provisional row.
    2. The requestSummary.egressClass stamped once on the provider-invocation row.
    3. The profile's declared egress ceiling.
    4. The committed artifact's egress class.

    Reading the write-once invocation row means the verdict survives the provisional row's deletion, so a remount after a downgrade still reads withdrawn, not stalled.

  5. Which previewTurnNarrative arm carries the draft text?

    1. Every servable arm.
    2. streaming and committing.
    3. Only streaming.
    4. streaming and withdrawn (for the notice).

    Every other arm is { state, released } (plus a closed reason on withdrawn); the tests assert the exact key set.

  6. The operator presses Stop while the draft is streaming. What does the panel do with focus?

    1. Moves it to the withdrawn notice.
    2. Leaves it where the operator's cancellation_requested transition put it; the notice only announces.
    3. Moves it to the composer.
    4. Moves it twice: first to the notice, then to the status.

    The operator's own move wins; the withdrawn notice has role="alert" so screen readers still hear it without a focus move.

  7. What does the client's single ttlMs deadline timer provide that the server-side preview query does not?

    1. It deletes the expired row on the server.
    2. A wall-clock drop: when the returned ttlMs elapses with no new server data, the client re-derives to stalled and stops painting the text.
    3. It re-authorizes the operator on the client.
    4. It advances the draft ordinal so the next delta starts a new draft.

    The preview reports stalled only when it re-runs; the client timer is the one clock-driven signal, which is why every text-bearing arm must carry the expiry guard.

  8. What did the round-1 review find in deriveAthenaProvisionalState?

    1. The precedence order was wrong.
    2. Three text-bearing arms lacked the rowExpired guard, so an expired truncated or committing row never fell through to stalled.
    3. The withdrawn arm fired before a release.
    4. The disabled arm was unreachable.

    The fix adds the guard to each of those arms and precedence rows for the expired combinations, so an expired row always yields to stalled.

  9. How was the narration directive accepted for the dev deployment?

    1. The deployed smoke emitted at least one delta with the mock model.
    2. A real operator turn's [agentHarness:driveTurn] log line showed narrative_delta before the first tool_call_requested.
    3. The contract suite's narration case passed against both adapters.
    4. The fence script reported deployedMatchesEpoch: true.

    The smoke's single-tool prompt is exactly the configuration that suppresses narration, so only a production-shaped turn read from the log proves the directive works.

  10. What is true about the dev deployment's state after this delivery?

    1. The fence advanced the durable epoch to the new digest.
    2. The new code and schema are deployed and new turns run, but the durable epoch still pins the previous digest because the fence step was skipped by operator direction.
    3. The daily_operations profile was disabled for the smoke and re-enabled afterwards.
    4. Production was deployed from the worktree.

    The fence compares epoch numbers, so new turns are not fenced; deployedMatchesEpoch: false is informational and recorded in the handoff.
