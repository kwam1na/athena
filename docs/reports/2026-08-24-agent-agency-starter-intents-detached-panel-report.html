Executive Summary

This delivery rebuilds how the Daily Operations agent works and how operators reach it, in seven connected moves: agency levers that stop the harness from killing work it could have kept (budget exhaustion returned as a value, in-flight queueing, ceilings tuned from observed use to 48 calls and 4 attempts, denials that name the offending argument), truthful read ports (register sessions keyed by operating date, catalog-scale inventory bounds, a payment-mix label that stops accusing clean books), mechanical product tone (opaque-reference scrubbing plus money and date display annotation at the result boundary, so quoting the right value is the path of least resistance), a permanent measurement loop (a real-turn eval driver with deployment-digest fencing, and a profile-neutral scorecard any future surface inherits without edits), compiled starter intents (a tap runs a curated read before the model's first token, seeded into the transcript as a completed tool exchange under runtime protocol v3), POS offline-sync closeout workflow traces, and a detached, shell-owned agent panel with a floating launcher and a chat-shaped transcript.

The through-line is a single lesson the branch proves twice over: shape the input before policing the output. Instructions were the weakest layer every time they were measured; mechanism (disclosed units, annotated displays, pre-executed reads, guest-side budgets) is what moved the numbers.

Why This Mattered

Trace analysis of the live agent showed an operator experience quietly degraded at every layer. 94% of observed register-session reads answered partial because the port scanned status partitions instead of the operating date. 100% of replenishment reads hit a 200-SKU ceiling sized far below the ~1,300-SKU catalog. Every money figure risked being quoted 100x too large, because capability results carried minor units with no unit disclosure. Tone violations were the top completeRun retry (9 of 13 retried turns), and each denial cost a full provider round. Budget overruns crashed programs and lost everything they had already read.

On top of that, a starter-intent tap was just a prefilled prompt: the model spent one whole provider round (~5-8 s of a ~14 s p50 turn) authoring a program the profile could have written better itself. And the panel lived inside the route, so navigating away destroyed the conversation's local state.

The Mental Model

Think of the harness as a restaurant kitchen serving a very literal-minded chef. The old kitchen handed the chef raw inventory codes and minor-unit prices, gave them a small pantry ration that ran out mid-dish (discarding the dish), and made every regular's usual order start from a blank ticket. The new kitchen labels every ingredient in the language the diner speaks (display strings for money and dates), lets the chef see the ration meter instead of hitting a wall (budget as a value), and for the four most common orders it preps the mise en place before the chef arrives: the curated read has already run, sits in the transcript as a completed exchange, and the chef's job collapses to plating — narrating an answer from data already on the counter.

The one untested bet — that a model handed a completed exchange commits first-pass instead of re-reading — was named in the plan as a falsification experiment to run before trusting the plumbing. It held: all four starter intents committed from the seeded exchange, citing its refs, with zero re-reads.

Before and After

Agency: before, budgets and concurrency were enforced only at the host bridge, so an overrun was a program crash that discarded every result already fetched; after, the QuickJS prelude mirrors a soft budget and an in-flight queue, so exhaustion is a returned value ({ kind: "denied", code: "budget_exhausted" }) the program can answer around, and the host bridge remains the hard backstop.

Reads: before, cash.registerSessions scanned the newest rows of every status partition (94% partial) and inventory paged 100 rows x 3 pages; after, register reads resolve through operating-date indexes and inventory pages 200 x 8 with an explicit page cost.

Tone: before, the model was instructed to sound like the product and mechanically punished when it did not; after, money and every date-only field carry sibling display strings into the model's view, known opaque references are rewritten to product phrasing at commit, and the bounded sensor is a backstop rather than the enforcement mechanism. On the 20-question regression set, jargon fell from 8.0 to 0.5 tokens per 1k characters and denials from 15/20 to 1/20.

Starter intents: before, a tap prefilled the composer; after, a tap submits immediately with the intent id, the server substitutes the pinned canonical prompt (client and deployment can never disagree about the question), the host runs the curated program through the production executor under the run's real grant, and the model wakes to a transcript in which the read already happened.

Panel: before, the agent surface was mounted under route content and its open state, draft, width, and scroll died on navigation; after, a shell-owned provider at the authenticated layout root owns the panel, a floating launcher activates the registered surface, and the pinned target survives reloads through validated sessionStorage state — restored closed, never as a surprise overlay.

What Changed and What Deliberately Did Not

Changed: the QuickJS prelude and validator (budget/date helpers, helper signatures), runtime ceilings, executeProgram and completeRun tool contracts (needs_clarification outcome, one-shot no_usable_sources pushback, deduped tone fixes), register/sales/inventory ports with implementationVersion bumps, the product lexicon (scrubOpaqueIdentifiers, annotateDateDisplays), the turn prompt (breadth, clarification, and display-verbatim guidance), runtime protocol v3 with preExecutedExchange across both adapters and the contract suite, turns.ts and runtimeHost.ts for starter-intent substitution and host pre-execution with its downgrade ladder, the eval driver and scorecard scripts, POS offline-sync closeout traces, and the whole panel surface including routes wiring, CSS, and the border-beam dependency.

Deliberately unchanged: the scratch tool is untouched (reserved for future cross-turn memory work). The egress checkpoint stays exactly at finishAttempt — the pre-executed program passes through it like any dispatched call. The pre-executed exchange never enters the tool-dispatch ledger; it is rendered into the provider transcript and is not a dispatch. The default model stays gpt-5-mini: gpt-5 was measured (broader reads, zero tone findings) and rejected for 2-3x latency and ~5-7x cost. And the kernel-rendered zero-provider-round answer was considered and explicitly rejected to protect the conversational surface, recorded so a future latency push can revisit it deliberately.

Failure Boundaries

Starter intents fail open, in one direction only. A malformed starterIntentId is the single hard refusal (starter_intent_invalid). Everything downstream downgrades to a normal free-form turn with a durable trace naming why: intent_unknown (panel/deployment skew during rollouts), no_program (intent without a curated read), render_failed (a template placeholder that is not a known snapshot key, or a value with the wrong shape), and handler or executor failures at pre-execution time. The one non-downgrade exit: if authority revocations arrive during pre-execution, the turn cancels through the existing authority_revoked path before any provider call — withheld-at-finish is an authority signal, not an executor failure. A resumed turn never re-runs pre-execution.

Budget exhaustion inside a program returns a denied value and the program keeps its prior results. The guest budget is per-program while the run ledger spans programs; the ledger remains the hard limit. Tone enforcement denies at most once per cause — a repeated honest submission is accepted. Shell restore validates everything it reads from sessionStorage (version, profile registry membership, context key completeness, store binding) and discards the stored target on any mismatch rather than restoring a wrong context.

Next Time

When model output violates a convention, ask first what the harness knew and did not disclose. Instructions were measured twice on this branch and lost both times; disclosure and annotation won. When adding a new agent surface, the scorecard and eval driver need no changes — add scenarios, tag a drive, and compare medians over N tagged drives, never single samples.

When adding a starter intent: write the curated program in the registry keyed by (profileId, intentId), keep placeholders to snapshot keys with declared shapes, and let conformance validate the rendered source against the real facade. If a future change moves where the pre-executed exchange is injected, re-read the plan's rejected alternative — fenced-prompt injection moves the egress checkpoint into prompt assembly and was rejected by three independent review findings.

When extending the shell: never infer an assistant context from the URL; only a contextual entry click or New thread re-pins. Persist reconnect handles and bounded context metadata, never prompt text or model-authored content.

Comprehension quiz

Pass required: 8 of 10.

  1. How does a starter-intent tap's curated read reach the model?

    1. The read's results are pasted into the operator question inside the untrusted-data fence
    2. The host runs the program before the first model step and seeds it into the transcript as a completed athena.executeProgram exchange
    3. The panel executes the read client-side and sends the rows with startTurn
    4. The model receives a hint naming which program to write, then writes and dispatches it itself

    Protocol v3 carries a preExecutedExchange that the adapter renders as a synthetic assistant tool-call plus tool-result pair before the first model step. A tool exchange is the representation the model is post-trained to continue from — that is the whole first-pass-commit bet. Fenced-prompt injection was explicitly rejected in review.

  2. A panel ships with a starter intent id the deployed backend does not know. What happens when an operator taps it?

    1. The turn is refused with starter_intent_invalid
    2. The turn waits for the deployment to catch up
    3. The turn downgrades to a normal free-form turn, with an intent_unknown skip trace
    4. The panel falls back to drafting the prompt into the composer

    Panel/deployment skew is routine during rollouts, so unknown ids downgrade instead of refusing — refusing would strand operators for every deploy window. Only a malformed id (failing the shape pattern) is refused outright.

  3. Why does the pre-executed read charge the run's real budget and pass the normal egress checkpoint?

    1. Because the budget ledger cannot distinguish host calls from model calls
    2. Because the curated read runs through the production executor under the run's grant — it is a real read with real egress, not a cached snapshot
    3. To make the eval driver's call counts comparable across scenarios
    4. Because Convex actions cannot skip the checkpoint

    The host invokes the same registered executeProgram handler the model would, under the same grant and admission. Keeping the egress checkpoint at finishAttempt untouched was a load-bearing design constraint — the rejected design moved it into prompt assembly.

  4. What does a program see when it exceeds the guest-side call budget mid-execution?

    1. The sandbox throws and the attempt is discarded
    2. The facade resolves { kind: "denied", code: "budget_exhausted", retryable: false } and the program keeps its prior results
    3. The call silently returns empty data
    4. The host pauses the program until the next attempt's budget refills

    Refusal-as-value is the core agency lever: exhaustion becomes something the program can answer around instead of a crash that loses everything already read. The run-wide ledger remains the hard backstop.

  5. The tone work's central finding, measured twice on this branch, is:

    1. Stronger enforcement denials produce cleaner prose
    2. Larger models follow tone instructions reliably
    3. Instructions are the weakest layer — disclosing units and annotating displays at the input boundary is what moved the numbers
    4. Tone sensing must run on the model-submitted text, not the committed text

    Enforcement without disclosure made prose worse (8.0 → 10.9 jargon tokens/1k chars, 73 s p90 retry tails). Input shaping — money and date display siblings, unit disclosure — took jargon to 0.5/1k with denials at 1/20. And measurement is of committed text.

  6. Why do money and date values keep their canonical forms alongside the new display strings?

    1. Backwards compatibility with older panels
    2. Programs and filters still consume canonical values; only the model-visible copy gains display siblings, and product-authored displays win over generated ones
    3. The display strings are locale-dependent and unstable
    4. Canonical values are needed to compute citations

    The rule is 'preserve canonical values and annotate the model-visible copy': programs keep YYYY-MM-DD and minor units for computation, while the provider-returned result gains UTC-pinned display siblings the prose quotes verbatim.

  7. What did the payment-mix investigation conclude?

    1. A reconciliation defect was corrupting 81 days of sales data
    2. There was no data bug — the flagged days predate the feature, and the port's label was accusing clean books of not reconciling
    3. The mix computation double-counted split tenders
    4. Momo payments were misattributed to cash

    All 81 flagged days predate payment-mix recording. The fix is truthful labeling: payment_mix_not_recorded instead of payment_mix_does_not_reconcile. A harness must not turn absence of data into an accusation.

  8. An offline register closeout syncs up needing manager approval. What does the workflow timeline now show that it did not before?

    1. closeout_submitted and approval_pending trace stages recorded at projection time, with the approval request id
    2. The manager's eventual decision, backfilled to the closeout time
    3. A synthetic approval auto-granted for offline events
    4. Nothing changed for offline closeouts

    Before, the trace only began when the manager acted — a hole in the timeline exactly where the variance was. Projection now emits both stages with syncOrigin local_sync, matching the online path.

  9. The panel moved out of the route and into a shell-owned provider. What alone is allowed to change the pinned conversation context?

    1. Any route navigation that renders a different store surface
    2. A contextual entry click or New thread — visible navigation is not authorization to change what the assistant answers about
    3. The sessionStorage restore on reload
    4. The launcher's open/close toggle

    Route navigation alone never re-pins; the origin context stays pinned until the operator explicitly switches. Restore brings the target back validated but closed, and the launcher toggles visibility, not context.
