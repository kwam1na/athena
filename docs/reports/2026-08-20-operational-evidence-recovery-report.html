Executive summary

This candidate closes a set of operator-review gaps where Athena already held the underlying fact but did not carry enough context into the surface where a manager had to act. Reports now expose transaction and expense evidence more explicitly, still-open registers remain visible across operating dates, workflow traces explain actors and cash impact, quick-add can preserve known unit cost, and inactive staff can be restored through a new command on the existing operation-admission rail.

The implementation extends existing contracts, ledgers, and read models. It does not introduce a second reporting system, a new audit ledger, or a production backfill.

The candidate also stabilizes the GitHub-hosted coverage boundary that blocked this already-validated product work. CI now runs the same full coverage policy with one Athena worker and GNU resource diagnostics; local coverage retains its two-worker default.

Why this mattered

Several workflows forced operators to reconstruct meaning from adjacent screens: expenses were compressed into a summary metric, prior-day open drawers could disappear from today's close posture, register traces used generic event text, weekly reports omitted transaction comparison, and known quick-add cost could still become uncosted inventory.

The sharpest failure was a non-cash void. Eligibility originally depended on positive cash impact, so card and mobile-money voids could have no register trace. Reusing drawer delta as transaction value then risked describing a real void as zero.

Delivery then hit a separate infrastructure failure: two GitHub attempts completed all 768 Athena test files and 9,191 tests before Vitest timed out waiting for an onTaskUpdate acknowledgement. Reporter-only tuning was already active, so another blind retry could not make the job structurally reliable.

Mental model: carry the fact to the decision

Think of each source record as the ledger and each operator surface as a lens. The lens may rank, label, compare, and link facts, but it must not invent a value or replace the ledger.

Command and source ledger → explicit optional contract fields → bounded read-model enrichment → operator presentation. Missing rollout evidence stays missing; it is not coerced to zero.

For CI, think of workers as producers and the Vitest main process as the acknowledgement lane. Two coverage workers can saturate a constrained runner while the main process still owes time-bounded RPC replies; one worker lowers concurrent pressure without shrinking the work.

Before and after

Before: manager emails mixed expenses into general metrics, open-register checks were day-scoped, trace rows lacked usable identity and financial context, and recovery actions required workarounds.

After: expense totals and ranked product evidence have their own section; all still-open store register sessions (open, active, or closing) that existed by the selected day boundary can block close with carried-over labeling; register events explain value, tender, actor, approver, and drawer impact; quick-add can establish known cost basis; inactive staff have an explicit reactivation action.

CI before: the same hard-coded two-worker coverage pool ran locally and on GitHub, and a fully passing suite could fail during worker reporting. CI after: GitHub explicitly selects one worker, logs the selected limit, and records elapsed time and peak resident memory around the unchanged root coverage policy.

What changed and what did not

  • Daily and weekly manager reports make transaction volume first-class and rank five products. Daily expense rankings require complete evidence; weekly rankings may disclose bounded partial coverage.
  • Daily Operations treats the live all-active-register query as authoritative and labels sessions opened on another operating date.
  • Workflow trace reads hydrate store-scoped staff, register, terminal, and currency context while preserving stored transaction and cash details; the UI renders operational sentences and transaction links.
  • Quick-add accepts an optional validated minor-unit cost and selects known versus uncosted inventory basis accordingly.
  • Staff reactivation uses the existing operation-admission rail and restores credential status based on whether a PIN exists.
  • Adjacent convergence fixes add progressive expense loading, SKU barcode and Adjust Stock navigation, shared register session-code identity, opening-float explanations, and scoped product-name normalization.
  • GitHub coverage uses one Athena worker through ATHENA_COVERAGE_MAX_WORKERS; the package default remains two workers, and the root harness test pins both the limit and resource-diagnostic command.
  • Intentionally unchanged: source ledgers remain authoritative, trace writes remain best-effort, omitted unit cost remains uncosted, and no historical trace backfill or production deployment is included.
  • Also unchanged: every test file, coverage threshold, failure exit code, and root coverage phase remains authoritative. The change adds no retry and suppresses no Vitest error.

Failure boundaries

  • Incomplete expense evidence still shows totals but suppresses product ranking, avoiding false precision.
  • Weekly transaction comparison remains optional when any contributing period lacks the metric; absence is not zero.
  • Trace identity joins stay store-scoped and fall back to generic wording when a profile is unavailable.
  • A void's transaction total and drawer delta are separate facts; zero cash impact does not make the void ineligible for evidence.
  • Unit cost must be a nonnegative safe integer in minor units. Omitting it preserves the existing uncosted path.
  • For this incident, the repeated post-suite RPC timeout is investigated separately because the logs prove every file and test completed. Future RPC errors still require evidence-based classification; named test timeouts and assertion failures remain genuine blockers.
  • One worker may increase wall time, so GitHub logs the limit and GNU time resource summary; duration and maximum RSS are the evidence for any later concurrency change.

Validation and delivery status

The representative CI=true run completed all 768 Athena files and 9,191 tests in 1,020 seconds with no worker RPC timeout. Storefront coverage also passed. The enclosing root sensor then failed on the deliberately stale workflow-contract assertion, proving a genuine downstream failure still propagates; after updating that assertion, the root harness suite passed 1,380 tests.

Workflow parsing, focused contract coverage, solution frontmatter, compound validation, and Graphify regeneration passed. Independent review evidence, the full bun run pr:athena gate, and the representative GitHub-hosted reruns remain pending on this exact delivery candidate.

Production deployment is intentionally excluded from this delivery. Root alignment is pending the merged PR.

Guidance for the next change

  • Carry a new operational fact end to end: command, source ledger or event, shared contract, read model, then presentation.
  • Test both complete and missing evidence. Never use zero as a convenient substitute for unknown rollout data.
  • Keep transaction value, payment allocation, and drawer movement as distinct fields even when one screen presents them together.
  • Prefer live blocker reads over frozen snapshots for current operational authority, while retaining snapshots for historical explanation.
  • Normalize human-facing labels at the authorized presentation boundary when stored audit evidence must remain unchanged.
  • When all tests pass before onTaskUpdate times out, measure worker/main-process pressure before changing test budgets; reporter formatting alone may stop being sufficient as the suite grows.
  • Do not raise GitHub coverage concurrency without comparing wall time and maximum RSS from the timed authoritative command.
