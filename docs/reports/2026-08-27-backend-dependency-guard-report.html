Executive summary

This delivery installs a shrink-only backend dependency guard (U1) that snapshots current Convex backend dependency cycles and fails only on new violations while protecting the inventoryLedger and agentHarness kernels from importing product domains.

The guard uses a committed baseline of exact violating edges/SCC identities. Baseline drift fails until regeneration contracts it; a removed edge cannot pay for a new cycle elsewhere. Legitimate same-transaction domain helper imports (leaf helpers) remain legal via an explicit allowlist.

The check runs as `bun run dependency:check:backend`, is harness-owned, deterministic, and blocks only new violations. All 1504 harness tests pass, architecture boundary checks pass, graphify check passes, and typecheck passes.

Problem

Athena's Convex backend has grown to ~245K lines across 199 tables and 617 admitted operations. Over time, implicit dependency cycles formed between modules, making changes risky and harder to reason about.

The inventoryLedger kernel (which owns all inventory valuation, costing, and stock movement logic) was importing product domains like operations, reports, cashControls, and stockOps. The agentHarness kernel (which owns agent lifecycle, completion, evidence, and runtime contracts) had similar unwanted coupling.

Without a structural guardrail, new cycles could form silently, and product-domain churn could destabilize the core transaction kernels that encode Athena's strongest business invariants.

Mental model

Think of the backend as a directed graph of imports. Some modules are kernels — they encode core invariants and must remain stable. Other modules are product domains — they implement features and churn more rapidly.

The guard draws a line: kernels may import platform primitives (convex/values, convex/server, generated types) and their own leaf helpers, but NOT product domains. Product domains may import kernels (that's the normal dependency direction).

A baseline captures today's cycles. The rule is shrink-only: the baseline can only contract over time as we refactor cycles away. New cycles are blocked. This is not a layering rewrite — it's a ratchet that prevents regression while allowing intentional improvement.

Before vs after

Before: No structural guard existed. inventoryLedger/effects.ts imported convex/operations/inventoryMovements and convex/operations/skuActivity. inventoryLedger/corrections.ts imported convex/operationAdmission, convex/platform/operationAdmission, convex/reports/access, and convex/storeTime/operatingPeriods. These were grandfathered as known violations in the baseline.

After: A deterministic check (`scripts/convex-backend-dependency-check.ts`) scans all 737 Convex source files, builds a dependency graph, finds SCCs via Tarjan's algorithm, and compares against the committed baseline (`scripts/convex-backend-dependency-baseline.json`). The check runs in CI and blocks on: (1) new dependency cycles, (2) new kernel violations (forbidden or not-allowed imports), (3) baseline drift (removed cycles without regeneration).

The 7 existing kernel violations in inventoryLedger are grandfathered in the baseline. They will be addressed by downstream units (U18 schema composition, U20 POS projector split, U21 catalog import split) that extract the offending logic into leaf helpers or platform modules.

Next-time workflow

To add a new protected kernel: add an entry to PROTECTED_KERNELS in convex-backend-dependency-check.ts with root, allowedImports, forbiddenImports, leafHelpers, and excludedPaths.

If a new cycle is detected: refactor to break it (move shared logic to a leaf helper or platform module) rather than updating the baseline. Use --update-baseline only after intentional cycle removal.

If a kernel violation is detected: the imported logic likely belongs in a leaf helper (only generated types + convex/values) or a shared platform module. Do not add product domains to allowedImports.

Downstream units that will reduce baseline violations: U18 (schema composition), U20 (POS projector split), U21 (catalog import split), U22 (cash-controls consolidation). These will extract the offending logic into proper leaf helpers.

The baseline file (scripts/convex-backend-dependency-baseline.json) is the contract — it should only shrink over time.
