Executive summary

This candidate repairs a replacement POS browser by keeping the original cloud register session canonical, replaying every eligible event found at execution time, transferring terminal authority, and queuing exact local review cleanup.

It also closes the follow-on void gap: a reopened closeout can accept a void for a sale created on the retired terminal, while authentication and drawer cash mutation use the replacement terminal that currently owns the session.

Why this was needed

Clearing browser identity created a replacement terminal and duplicate local drawer. Cross-terminal inference correctly stopped, leaving sales in sync review. The GHS638 value was a physical cash count, not another opening float.

After the handoff fixed sync review, completed-sale voids still failed because closing sessions were treated like new-sale sessions and the sale's immutable historical terminal was incorrectly reused as current authentication and cash authority.

Mental model: ledger, provenance, and current key

The cloud register session is the ledger for one physical drawer. A transaction's terminal id is immutable provenance: it says which browser recorded the sale. The register session's terminal id is the current key allowed to authenticate and mutate drawer cash.

A handoff changes the current key and records the old key in append-only lineage. It does not rewrite sales, create another float, or discard the physical count.

Before and after

Before: replacement identity → duplicate open and unmapped sales → sync review. After handoff: execution-time reread → durable mapping → supported replay → conflict settlement → authority transfer → local cleanup command.

Before void fix: closing session blocked the action, and old-sale terminal identity could not authenticate or record cash. After: a void-specific lifecycle policy allows open, active, or closing; exact-session lineage validates historical provenance; current session terminal authenticates and records the cash reversal.

What changed and what did not

The handoff mutation does not trust caller-selected review ids. It rereads the exact replacement drawer, applies completeness sentinels, consumes approval only after preflight, and rolls back the whole Convex transaction on projection drift.

The transaction read model now exposes the current register-session terminal for void authentication. The public mutation independently verifies handoff lineage and rejects proof from the retired terminal. The approved void passes the current terminal into the real register-session cash handler.

  • Historical transaction terminal attribution remains unchanged.
  • GHS638 remains physical-count evidence and never becomes a second opening float.
  • Payment-method correction remains unavailable while the drawer is closing; the new authority selection is void-only.
  • Closed, closeout-rejected, wrong-store, unrelated-lineage, incomplete-history, and stale-authority cases fail closed.
  • Brush-roller net price remains GHS30; catalog or pricing policy is not relaxed.

Failure boundaries

Handoff evidence reads stop at 501 rows and replay stops above 20 events or 100 sale/service lines. Historical-terminal lineage lookup fails closed beyond 20 handoffs; a sale on the current terminal does not consult that history. A concurrent authority change makes the real cash handler reject the stale terminal and Convex rolls back.

Cloud settlement is not browser convergence. Production completion still requires the replacement browser to acknowledge clear_local_review_items and then report a fresh zero-review heartbeat.

How to extend or operate this safely

  • Keep historical provenance separate from current session authority.
  • Reread exact-session pending evidence inside the mutation; UI snapshots are hints, not repair scope.
  • Require current-terminal staff proof even when lineage authorizes an old sale.
  • Pass the same authoritative current terminal to drawer cash recording.
  • After production repair, verify session owner, unchanged opening float, expected cash, resolved conflicts, retired old terminal, cleanup acknowledgement, and a fresh zero-review heartbeat.
