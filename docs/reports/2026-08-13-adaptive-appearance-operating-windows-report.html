Executive summary

This candidate makes four operator-facing views tell the truth about time and state. Athena can follow local sunrise and sunset, register transaction history follows the full session lifecycle, historical Daily Operations keeps open-register evidence with close status, and report summaries name their exact date range.

The changes share one principle: compact controls select intent, while the browser resolves solar boundaries and the backend resolves register closure.

Why this mattered

A register opened across multiple operating dates could show only transactions from its opening day in Completed Transactions. Historical close evidence and open registers could split into separate bands, report tabs hid their actual dates, and appearance schedules depended on manual or operating-system choices rather than local daylight.

  • The previous register handoff treated an opening date as a one-day filter.
  • Historical status composition did not match the current-day workspace.
  • Compact report period names lacked an exact range in the status context.
  • Theme state had no contextual, browser-local sunrise/sunset mode.

Mental model

Treat identity, time, and presentation as separate rails. Identity stays invariant: a register-session filter remains attached in every segment. Time is resolved by the layer with authority: the server knows session closure, while the browser knows local solar context. Presentation states the resolved result without overloading navigation labels.

Before and after

Before: a register opening date became both lower and upper operating-day bounds; historical evidence occupied parallel surfaces; report periods were named but not dated; theme resolution understood only explicit and system choices.

After: the default register view starts at the opening-day boundary and ends at recorded closure only for closed sessions; All Time remains an identity-only audit view. Historical evidence shares one Store day status workspace. Report status metadata includes the formatted interval. Sun cycle requests coarse location on selection, calculates the current solar period locally, and schedules the next transition.

Failure boundaries

A denied or unavailable location request preserves the current mode and shows recovery guidance; cancellation preserves it without showing an error. The AbortSignal does not cancel the browser request itself—it prevents applying a late successful callback. If Sun cycle is already stored but its coordinates are missing or corrupt, effective appearance falls back to the system preference. Polar day or night currently makes activation unavailable rather than maintaining continuous daylight or darkness.

A lifecycle start-only query is accepted only with a register session, and missing or cross-store sessions return no rows. Closed sessions exclude post-closure records only when status is closed and closedAt is numeric; an inconsistent closed session without closedAt remains unbounded. All Time deliberately exposes post-closure records for audit.

  • Today still intersects today with the register identity.
  • Non-register queries still require paired start and end dates.
  • No anomalous transactions are repaired or deleted.
  • No location is stored on the server or synchronized across devices.

What changed and what did not

The branch adds runtime, component, query, and regression coverage for the four refinements. Existing explicit appearance choices, saved dark palette behavior, closeout policy, Cash Controls linked-sales semantics, standalone transaction history, and report comparison calculations remain unchanged.

  • Sun-cycle coordinates are rounded to 0.01 degrees and remain in localStorage.
  • Automatic theme changes avoid attention-grabbing manual transition effects.
  • Review-only sessions opened before the selected range now contribute to carried-over session evidence and cash without entering active or closed totals.
  • The report range is quiet metadata beside reconciliation status, not a longer segmented-control label.

Guidance for future changes

Keep entity identity orthogonal to time-window selection. Put lifecycle cutoffs on the server that owns status and closure facts. Keep verbose temporal context in quiet metadata. For adaptive browser preferences, request sensitive context only when selected, minimize what is retained, schedule the next boundary, and recalculate after sleep or focus.

  • Test active, closing, closed, missing-closedAt, Today, lifecycle, and All Time paths separately.
  • Reconcile UTC-normalized solar events to the device's local calendar day, with DST, date-line, and high-latitude fixtures.
  • Use one shared status composition rather than parallel historical notification bands.
  • Regenerate Graphify after code edits and refresh report/solution fingerprints after final behavior changes.
