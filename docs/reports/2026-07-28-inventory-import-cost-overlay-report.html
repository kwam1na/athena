Executive summary

Source stays exact

CSV duplicate columns retain label and ordinal; JSON values retain their path. Zero is valid. Missing, malformed, negative, over-precision, out-of-range, and conflicting values remain explicit evidence states.

Writes stay prospective

Apply uses the existing reporting-owned valuation correction. It changes the SKU cost and prospective cost basis without rewriting historical sale cost.

Undo stays compensating

Undo appends an exact-basis compensation only when SKU, valuation, and lineage fingerprints still match. Changed rows become stale exceptions instead of being overwritten.

Intentionally unchanged: stock counts, availability, selling prices, product identity, historical sale cost, and the existing manager-enabled onboarding flow are not rewritten by this feature.

A sealed manifest followed by fenced, one-row financial work.

Mental model

  1. Choose
    Select the exact saved legacy column.
  2. Freeze
    Build one durable row per anchored SKU.
  3. Review
    Filter, search, and make truthful decisions.
  4. Seal
    Prepare a digest and aggregate impact.
  5. Apply
    Correct one SKU per transaction.
  6. Compensate
    Undo only unchanged post-apply rows.

Epochs and worker generations act like track switches: queued work from an earlier direction cannot cross into a later apply, retry, or undo phase.

Large review transport

The browser stages payload chunks at no more than 240 KiB each, with an 8 MiB aggregate limit. Upload sessions are owner/store-bound, capped at five active saves per operator/store, expire after one hour, and clean up abandoned chunks. Small staged reviews can still hydrate through the legacy latest-review API when the complete legacy response fits the explicit 896 KiB compatibility envelope.

Decision truthfulness

System-owned ineligible is not a public command input. A missing-cost row may use selected_missing_cost; a known-cost row requires explicit overwrite_selected. Server-side bulk work skips incompatible rows and records only actual changes. The Costs differ filter includes only rows where both costs are known and their minor-unit values are unequal; missing Athena costs remain in the missing-cost path.

Partial undo authority

Finalization trusts an overlay cost only when linked run provenance, row state, provisional markers, and current SKU cost agree. That remains true during undoing and for undo_exception rows after a partial undo; successfully undone, mismatched, or superseded rows stop being authoritative.

Bad inputs and interrupted work fail into visible states.

Failure boundaries

Hard scope ceilings

8 MiB saved review, 36 transport chunks, 5,000 construction anchors, 100 frozen lineages per SKU, 10 active runs per store, and 334 URL-restored UI pages.

Bounded continuations

Construction commits up to 1,000 rows per action; bulk decisions use 50-row batches; undo preview uses 10-row batches; financial apply and undo stay one row per transaction.

Recovery leases

Heartbeats classify interrupted work after 60 seconds. Retry atomically advances an epoch or generation before scheduling, so repeated recovery does not fork continuation chains.

Best-effort undo

Any post-apply SKU, valuation, deficit, or lineage drift makes the row stale. The worker records the exception and continues; it does not force a global rollback.

Operational note: worker batch size favors atomicity and recoverability over throughput. The first production-scale run should be monitored for scheduler latency. Browser validation remains explicitly assigned to the operator for this delivery.

Three different failure states

  • Apply exceptions are row-local outcomes such as stale_before_apply, a deficit-blocked correction, or a valuation-domain error. The run continues and records the exception.
  • Interrupted work is a non-terminal phase whose heartbeat went stale. Resume claims a new epoch or generation and continues from the durable cursor.
  • Undo exceptions are terminal evidence that a row could not be safely compensated. Still-effective undo_exception rows keep their overlay authority until successful undo or superseding SKU evidence removes it.

Hard ceilings fail closed. Oversized review transport is rejected with staged-save guidance; construction above 5,000 anchors is durably abandoned with an explicit scope reason, requiring the operator to narrow or restart the run.

Authorization after confirmation

Revoked or unauthorized users immediately lose reads and new public commands. Already-confirmed internal work continues against frozen store, actor, source, epoch, and row evidence so a later role change cannot leave a half-applied financial run without an owner.

How to extend or debug this area

Next-time guidance

  1. Start from the saved review version and exact source-column identity; do not infer cost from normalized preview fields.
  2. Keep public operations admitted and idempotent. Add a request ledger when historical replay must remain meaningful.
  3. Put financial writes through reporting effects and refresh SKU search projection in the same transaction.
  4. When adding worker phases, persist cursor, epoch/generation, heartbeat, counts, and a visible terminal failure state.
  5. For undo changes, test both exact compensation and the stale path after deliberate post-apply edits.
