One timestamp primitive, and the popper bug it uncovered.

A relative label with the exact time one hover away, adopted across the surfaces where the exact time changes a decision. Measuring the tooltip in the browser turned up a global popper-positioning defect that predated the work.

Branch: relative-timestamp-componentFocused tests: 1,000+ passedPR: pendingDeploy: pending mergeRoot alignment: pending merge

Executive summary

The register session trace view's relative-label-with-tooltip pattern becomes a ui/ primitive and is adopted at 28 call sites across transactions, orders, expense reports, the operations queue, five event timelines, SKU activity, and the order detail view. Roughly fifty sites previously rendered a relative label with no way to reach the exact time.

Verifying the primitive in the running app exposed a separate, pre-existing defect: the admin shell's zoom: 0.95 made every Radix popper drift by up to ~70px. That fix is global and lands here. Two smaller asks ride along — weekdays on register session open/close dates, and a transaction count beside units in the reports trend tooltip, which required plumbing a new optional field onto the persisted overview projection.

Mental model: the label is a summary, not the value

A relative label answers "roughly when", which is what scanning needs. The exact timestamp answers "which shift, which day, before or after the count" — which is what deciding needs. The primitive keeps both in one element so a surface never has to choose, and so the machine-readable value travels with the human-readable one.

lib/utils owns the two format functions; nothing about presentation.
ui/relative-timestamp owns the label, the <time dateTime>, and the tooltip.
index.css keeps overlays positioned correctly under the shell's zoom.
Call sites pass a value and, where the copy needs it, a prefix or fallback.

  • Radix tooltips do not open on tap, so the absolute value is unreachable on touch surfaces.
  • A day with no register close carries no transaction count.
  • Persisted overview documents show units alone until the next sweep.
  • Three string-building call sites keep the raw helper by design.

Next-time guidance

  1. Extract on the second independent implementation of a pattern, not the third.
  2. Measure a positioning bug in the browser before naming a cause.
  3. Pair a popper trigger to its content by aria-describedby, never by document order.
  4. Add a dedicated formatter when a shared one serves several meanings.
  5. Check what a chart-test harness actually feeds the component before trusting a green assertion.

Quiz: Pass Required

Pass threshold: 8 of 10. Grade locally; no answers leave this file.

1. What signalled that the timestamp pattern should be extracted?

The trace view and ProductOperationalTimeline had the same shape, with byte-identical formatters.

2. What actually caused the tooltip to render ~70px from its trigger?

The portal was the first hypothesis; measurement showed the offset unchanged, and that change was reverted.

3. Why does the offset grow toward the right of the screen?

Proportional error is invisible in a sidebar and worst in a right-hand column.

4. Why was the native title attribute removed?

A deliberate call: tap-to-open is the fix if a touch surface needs the value, not restoring title.

5. Which call sites deliberately keep getRelativeTime?

A string has no JSX seam to hand a component.

6. Why add session-only date formatters instead of changing the shared one?

Widening it would have leaked weekdays into surfaces nobody asked about.

7. Why can't dateStyle: "medium" simply gain a weekday?

Mixing them throws, which is why the parts are spelled out.

8. Why are trend transaction counts resolved at sweep time?

Resolving 30 closes per load — with a throwing open-day fallback — is the cost the projection exists to avoid.

9. What does the tooltip show for a day with no register close?

An invented zero would later contradict the closeout.

10. What is the finish-line status in this candidate report?

Candidate reports must not predict merge, deploy, or root alignment.
