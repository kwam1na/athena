Trust and failure boundaries

  • Both the summary and evidence queries require reports access for the requested store. A loaded POS transaction or storefront order must also belong to that same store.
  • Evidence examines at most 501 report facts and returns at most 500 grouped evidence rows. The extra fact is a sentinel: it makes truncation explicit instead of presenting a partial list as complete.
  • Only POS and storefront sources participate. Services and other movement types intentionally remain outside this sales-evidence sheet.
  • Missing, deleted, or malformed source records remain visible as an unavailable reference; they do not become cross-store data.
  • Current catalog price is identity metadata, not historical accounting. Unknown cost and profit stay unavailable rather than being guessed from today’s price.
Residual edge case. The fact cap is applied before filtering non-POS/storefront facts. A noisy day can therefore yield a disclosed but incomplete sales-evidence list. This is an intentional budget boundary, but a later refinement could target the source-domain filter more directly if that becomes operationally important.

What intentionally did not change

The report-fact and rollup schemas, aggregation rules, and primary Items query retain their existing meaning. This candidate does not rebuild report facts in React, add ingestion or migration work merely to support the sheet, or substitute current catalog values for historical sales cost.
