Executive Summary

This candidate delivers the complete dirty tree as one coherent order-fulfillment update. Customer emails now reflect real fulfillment milestones, canonical store hours, and the actual store identity; checkout and payment verification preserve product availability and shopper ownership.

The finish line is a merged pull request into main. Production deployment and local root alignment are intentionally outside this delivery.

Problem and Context

The previous behavior crossed several boundaries without carrying all required truth. The checkout read model dropped product visibility, Paystack references could reach an ID-shaped lookup, email previews described states that runtime dispatch did not send, and some paid-order paths still rendered Wigclub defaults for other stores.

A template-only fix would leave these runtime gaps intact. The delivery therefore follows the full path from status transition and owner-scoped lookup through persisted send markers and final email rendering.

Mental Model

Think of each email as the final projection of four authorities: the order owns the lifecycle state, Store Schedule owns recurring opening hours, the store owns identity and pickup location, and the admitted shopper scopes local order resolution and mutation after provider verification.

The renderer receives already-resolved display facts. It does not invent hours, infer ownership, or decide which transition deserves an email.

Before and After

  • Before: ready-for-delivery existed as a preview but was not scheduled or dispatched. After: it has a runtime branch and an independent sent marker.
  • Before: one readiness marker could suppress a later delivery milestone. After: ready-for-delivery and out-for-delivery remain independently reachable.
  • Before: paid confirmations could mix dynamic store data with Wigclub defaults. After: both POD and paid paths use the resolved store name and pickup location.
  • Before: checkout finalization could interpret missing isVisible as unavailable. After: the internal session read model preserves the product visibility fact.
  • Before: payment verification used a less-specific order lookup. After: the external reference is resolved through the admitted owner's scoped lookup.

What Changed and What Did Not

The shared OrderEmail component now renders fulfillment-specific status bands, optional pickup hours, dynamic branding, and dedicated preview fixtures. Fulfillment dispatch resolves an active schedule only for pickup-ready mail and persists successful sends. The operator payment rail has clearer method, verification, collection, and pending states.

The CI suite twice completed all 9,212 tests before Vitest 3.2.4 timed out reporting the final task update. The delivery now applies the narrow upstream runtime RPC fix through Bun's pinned dependency patch: the reporting RPC has no artificial deadline, while test execution timeouts and the one-worker coverage policy remain unchanged.

  • MailerSend remains the provider and the existing sending address remains unchanged.
  • Missing schedules remain non-fatal and omit the hours block.
  • Store-hour email rows use recurring weekly windows; date exceptions are not expanded into this message.
  • The prior one-worker coverage setting remains intact; this delivery fixes the reporting boundary instead of reversing that policy.
  • No production deploy is authorized by this delivery.

Failure Boundaries

  • MailerSend failure does not persist a sent marker.
  • Missing order or store data stops dispatch before the external effect.
  • A successful Store Schedule lookup returning null still allows pickup-ready mail without invented hours; a schedule-query exception aborts before MailerSend.
  • Shared-demo effects remain simulated through the existing capability boundary.
  • Payment verification rejects mismatched shopper identity up front; after Paystack verification, the owner-scoped query protects local order resolution and mutation.

Next-Time Guidance

  • Add orchestration coverage whenever a lifecycle preview or status branch is added.
  • Give independently meaningful customer milestones independent persisted send markers.
  • Use Store Schedule rather than automation settings for store-local hours.
  • After provider verification, resolve the local order with an owner-scoped indexed reference query, never raw document lookup.
  • Regenerate Convex API, operation-admission callers, and Graphify after changing these paths.
