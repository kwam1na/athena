Public Operation Admission And Shared-Demo/POS Polish

Delivery candidate that adds a public (anonymous) actor kind to Convex operation admission for the new register-interest surface, extracts shared-demo register-open timing into a tested module, and carries a batch of daily-operations, cash-controls, checkout, POS terminal, landing-story, and route/navigation fixes.

Executive Summary

This branch closes a gap in Convex's operationAdmission module: every mutation previously assumed a signed-in caller and threw for anonymous access. The new register-interest public form needs anonymous write access, so this delivery adds a third actor kind, public, that is admitted only when a mutation's definition explicitly opts in via actors.public: "admit". Everything else defaults to the existing fail-closed sign-in error.

Alongside that, the branch carries a wide but shallow batch of related fixes: shared-demo register-open timing moved into a dedicated, tested registerBaseline module; a store website field threaded through shared-demo provisioning; a resiliency fix for useManagerElevation so a transient Convex external-store tear no longer crashes the app; and touch-ups across cash-controls deposits, Paystack routes, checkout session creation, daily operations/opening/approval mutations, POS terminal health/detail views, landing story scenes, and route/navigation registration.

Problem And Context

Register-interest needed a Convex mutation that visitors without an Athena account could call. The only existing options were: bypass resolveOperationAdmission entirely for that mutation (losing the audit trail every other write goes through), or widen the normal-user adapter to tolerate missing auth (weakening the signal for every other, still-authenticated-only, mutation). Neither was acceptable, so admission needed a real third state.

Separately, shared-demo register-open timing (Math.max(operatingDayStart, now - 14_400_000)) was duplicated inline in two places in provision.ts with no test coverage of its edge cases, and useManagerElevation threw a fatal error whenever it rendered without a provider in the tree — including during a recoverable single-render Convex store tear.

Mental Model

Think of resolveOperationAdmission as a bouncer with two doors: the members-only door (normal user) and a side door (public) that is only unlocked for events that put it on the guest list. The bouncer always tries the members door first. If that fails because the person has no membership card (anonymous caller), it checks whether this specific event allows the side door before turning them away. Most events never unlock the side door, so the default behavior for every existing mutation is unchanged.

Before And After

  • Before: OperationActor had two kinds (normal_user, shared_demo); any anonymous call threw "Sign in again to continue." with no opt-in path.
  • After: a third kind, public, exists. resolveOperationAdmission only reaches it when the normal-user adapter throws, and only admits when definition.actors.public === "admit"; otherwise the original sign-in error is preserved and rethrown.
  • Before: register-open timing math was duplicated inline in provision.ts with no dedicated tests.
  • After: sharedDemoSeededRegisterOpenedAt({ now, operatingDayStartAt }) is a single tested function imported by provision.ts.
  • Before: useManagerElevation threw when called outside a provider, including during a transient concurrent-render tear.
  • After: it falls back to an inert, safe default value (INERT_MANAGER_ELEVATION) instead of throwing, so a recoverable render does not escalate to an error boundary.

Layer Breakdown

convex/operationAdmission/{types,definitions,adapters,actors}.ts define the actor/adapter contract. A new mutation opts into anonymous access by setting actors.public: "admit" in its definition; createPublicOperationAdapter reads that flag and either resolves scope constraints for an admitted anonymous actor or reports not_applicable. Call sites that read actor.athenaUserId (e.g. convex/lib/athenaUserAuth.ts) were updated to treat public as carrying no user id, using the new getOperationActorAthenaUserId/requireOperationActorAthenaUserId helpers from actors.ts rather than reading the field directly.

Independently, convex/sharedDemo/registerBaseline.ts is a new module (with registerBaseline.test.ts) that provision.ts now imports for register-open timing, and shared/sharedDemoStory.ts carries a store website field that flows through provisioning into the store config.

Failure Boundaries

  • A mutation that omits actors.public (or sets it to "deny") continues to throw "Sign in again to continue." for anonymous callers — the default is unchanged and fail-closed.
  • The public adapter only resolves scope constraints; it never fabricates an authenticated identity, so downstream code that needs a user id must call requireOperationActorAthenaUserId, which throws the same sign-in error for a public actor.
  • useManagerElevation's inert fallback only covers a single missing-provider render; it does not change behavior once the real provider mounts on the next render.

Intentionally Not Changed

  • Existing mutations that do not opt into actors.public: "admit" keep rejecting anonymous callers exactly as before.
  • The normal-user and shared-demo admission paths are untouched other than the added try/catch fallthrough to the public adapter.
  • Production deployment and root-repo alignment are not part of this delivery.

Next-Time Guidance

When a new mutation needs anonymous access, add public: "admit" to its actors block instead of bypassing resolveOperationAdmission. When touching any code that reads OperationActor.athenaUserId, use the actors.ts helpers rather than accessing the field directly, since a public actor carries no user id.
