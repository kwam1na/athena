Prior-period comparisons now carry their own truth.

Report metrics can show direction without asking React to reconstruct financial periods. Current and prior values move together from bounded Convex read models through stable UI transitions.

Executive summary

The change adds prior snapshots to overview rolling windows, prior day/week/month totals to item reports, and an equal-length prior range to SKU detail. Comparison arithmetic and source selection remain server-owned.

The UI receives explicit current and prior totals, retains the settled period key while new Convex arguments load, and uses one short reduced-motion-aware crossfade for comparison copy. Missing profit or price facts remain unavailable rather than becoming invented zeros.

Before

  • Rolling overview periods had no comparable prior snapshot.
  • Item and SKU views could show totals without direction.
  • Client surfaces risked independently defining “prior period.”
  • Old settled data could appear under a newly selected period label while refreshing.

After

  • Server-shaped contracts return explicit adjacent comparison totals.
  • Period semantics distinguish calendar month from equal-length custom ranges.
  • Legacy overview documents are enriched through an indexed 184-day cap.
  • Settled data and its context key transition together.

Mental model: one paired evidence packet

Think of every comparison as a sealed packet: the current window, its matching prior window, and the period identity travel together. The UI may format the packet, but it does not change what the windows mean.

Report projections fold source facts into bounded current and prior windows.
Shared contracts preserve totals, missing values, and period identity.
Stable query state keeps old data paired with its old context during refresh.
Metric components format and crossfade the already-decided comparison.
