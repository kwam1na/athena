Executive summary

Athena now resolves its portable delivery workflows through the final qualified core-v1 archive. The lifecycle, host projections, migration records, and exact-release sensors all point at one active generation.

This is a bounded portable-to-portable update. Athena remains authoritative through the same delivery system and retains its repository policy, gate, telemetry, reporting, pull-request, deployment, and full Linear overlays.

Why the switch was needed

Athena was already running the portable system, but on an earlier qualified archive. The final release contains the execution workflow refined by agent-skills PR #17 after the corrected product pilot exposed missing outcome observability. That exact source merge, f0a058d7b40a, qualified archive f8b39590bae7 with execute-work digest 33ee613ce298.

The repeated cross-repository pilot landed kwamina-fyi PR #12: one causal whitespace-tolerant sensor fix passed 315 JavaScript tests, 25 content tests, and the production build. It proved that the abstraction could improve diagnosis and select a smaller valid product diff; it did not by itself prove Athena installation or rollback.

The key risk was evidence ambiguity: accepting old shadow evidence merely because it once passed would be unsafe, while demanding a new shadow run for byte-identical canary semantics would add ceremony without observing anything new.

Mental model

Treat the installed portable core like a content-addressed tool chest. The release archive identifies the whole chest, while each workflow digest identifies an individual tool. A new chest requires a new exact receipt, but an observation of one tool remains meaningful only when that tool's bytes are unchanged.

The lifecycle remains the single switch. Both Codex and Claude follow relative links through .agent-skills/current, and rollback follows the retained prior generation recorded in the active receipt rather than a second orchestration path.

Before and after

Before: Athena's current link selected archive 004bfcf1c8d2 and the earlier execute-work body. The portable kernel, accepted shadow comparison, reversible canary, and batch migration were already established.

After: the same lifecycle selects archive f8b39590bae7 from source f0a058d7b40a. Five workflow bodies remain byte-identical; execute-work advances to digest 33ee613ce298. The canary accepts the historical comparison only because the kernel digest still equals d7a651c9392a.

What changed and what did not

Changed: the vendored archive and metadata, installed generation and active receipt, release and batch identities, execute-work digest, and exact-current sensor fixtures. Inside the qualified archive, lifecycle infrastructure also records and safely prunes lifecycle-created directories and gives a clearer remove path when a first install has no prior generation; Athena consumes those already-qualified lifecycle changes without adding another update mechanism.

Changed narrowly: canary admission validates historical shadow structure and accepted digest, then separately requires the observed canary workflow digest to equal the active canary digest.

Unchanged: Athena application behavior, host topology, repository overlays, runtime Linear capability, deployment behavior, and the existing lifecycle, telemetry, gate, canary, batch, and rollback planes. No durable plan-unit shorthand was added.

Failure boundaries

  • Archive, metadata, workflow, active-receipt, migration-record, host-link, predecessor, or inventory drift blocks admission.
  • A changed canary workflow digest invalidates shadow reuse and requires a fresh shadow observation before authority can advance.
  • The retained prior generation supports source-independent rollback and leaves unrelated repository bytes unchanged.
  • Qualification fixture hygiene does not cap production Linear create, read, update, search, relation, or reconciliation behavior.

Validation and finish-line status

Qualified archive integrity: agent-skills PR #17 passed 202 portable-core tests on macOS, Linux, and Windows, refreshed the exact core/provider/Linear qualification records, and produced archive f8b39590bae7.

Cross-repository product proposition: kwamina-fyi PR #12 records the corrected pilot's causal one-line sensor fix and its 315 JavaScript tests, 25 content tests, and production build. This demonstrates diagnosis and diff selection, not Athena integration.

Athena integration: 131 focused portable and telemetry tests; current portable canary and batch audits; source-independent rollback rehearsals; both host projections; and the full 1,698-test script harness are green. Generated Graphify output was rebuilt and generated-artifact preparation completed.

Independent final-green review, pr:athena, pull-request merge, and root alignment are pending at report creation. Deployment is not applicable because this infrastructure-only delivery does not change the application runtime.

Guidance for the next release

  • Build and verify the exact qualified archive before changing Athena's release records.
  • Compare the canary workflow digest, not just the archive label, before deciding whether historical shadow evidence still observes the active semantics.
  • Advance current release identities and every changed workflow digest together, then run the existing canary, batch, rollback, harness, review, and final gate paths.
  • Keep Athena policy in its overlays and avoid adding parallel caches, telemetry stores, orchestrators, or arbitrary Linear limits.
