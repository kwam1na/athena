Executive summary

This bootstrap records an operator-observed local product-maintenance snapshot for Athena's manual shadows and preserves the useful core already present in Athena: portable workflow definitions, repository-policy overlays, normalized candidate-bound evidence, review and validation records, and deterministic finish-line decisions. A fresh OS-native authorization approved the existing maintenance update; at that bootstrap-time observation sequence 2 was active, accepted, and pinned while sequence 1 remained the rollback target. This is not a repository sensor, durable guarantee, or automatic detector of later local drift.

It deliberately removes the attempted managed-admission and preparation-sensor layer. The coding host still orchestrates the work, bun run pr:athena remains repository-policy authority, and GitHub remains merge authority. The next evidence comes from three manual Athena shadows, not more machinery.

The product boundary

The product is a referee and evidence ledger beside Athena's existing delivery workflow. It does not launch agents, schedule subagents, manage sessions or worktrees, or replace Athena's repository gates.

Before manually recording a counted derived summary, the operator independently verifies and retains outside model grants the complete projection-consumption-observation/1 artifact: spec, deliveryId, fence, entry workflows/delivery-v1.json, canonicalProjectionPath, projectionDigest, hostInvocationId, and observedAt, plus immutable candidate and GitHub/pr:athena evidence. The operator must not record unsupported-host, path-only, echoed, cross-repository, symlinked/hardlinked, or protected-target-mismatched evidence. These are manual admission conditions and operator assertions. Athena's M1 entry retains only a derived source/affirmative/digest/marker summary plus candidate and GitHub evidence; the guard and scorer validate only those literal recorded inputs, not external retention or underlying provenance/path conditions. A counted entry therefore means the operator asserted these preconditions and the tools accepted the derived input; it does not itself preserve or prove the complete envelope, trusted operator intent, registration, takeover authority, model isolation, or writer provenance. The qualified Claude PostToolUse adapter produces that normalized contract now; a future qualified Codex native adapter must emit the same contract. Codex has no qualified binding or producer now, and it and all unqualified hosts remain excluded from counting.

Mental model: compare decisions, do not replace delivery

The coding host runs the delivery exactly as Athena does today. After final immutable delivery evidence, the operator independently verifies and retains the qualified host's complete observation outside model grants, then manually records its derived M1 summary with candidate and GitHub evidence. This is an operator admission assertion: the guard and scorer validate the recorded derived and candidate/GitHub inputs, not external retention, and cannot exclude a summary solely because the external artifact is later lost or unavailable. Athena and GitHub still decide whether the candidate is merge-ready and merged.
