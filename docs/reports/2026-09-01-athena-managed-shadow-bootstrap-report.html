Executive summary

This bootstrap activates and closure-verifies the current product generation for Athena's manual shadows and preserves the useful core already present in Athena: portable workflow definitions, repository-policy overlays, normalized candidate-bound evidence, review and validation records, and deterministic finish-line decisions. A fresh OS-native authorization approved the existing maintenance update, making sequence 2 active, accepted, and pinned while retaining sequence 1 as the rollback target.

It deliberately removes the attempted managed-admission and preparation-sensor layer. The coding host still orchestrates the work, bun run pr:athena remains repository-policy authority, and GitHub remains merge authority. The next evidence comes from three manual Athena shadows, not more machinery.

The product boundary

The product is a referee and evidence ledger beside Athena's existing delivery workflow. It does not launch agents, schedule subagents, manage sessions or worktrees, or replace Athena's repository gates.

A counting shadow may claim only that a qualified host emitted projection-consumption-observation/1 for a completed exact full Read, exact candidate-bound evidence was recorded, and Athena's repository policy passed. The qualified Claude PostToolUse adapter produces that normalized contract now; a future qualified Codex native adapter must emit the same contract. Codex has no qualified binding or producer now, and it and all unqualified hosts remain excluded from counting. This does not prove trusted operator intent, registration, takeover authority, or model isolation.

Mental model: compare decisions, do not replace delivery

The coding host runs the delivery exactly as Athena does today. The operator uses the product's existing primitives to materialize the pinned portable workflow, retain the qualified host observation with candidate evidence, and evaluate the deterministic comparison. Athena and GitHub still decide whether the candidate is merge-ready and merged.
