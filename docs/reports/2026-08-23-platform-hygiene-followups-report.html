Executive summary

The platform-hygiene epic deferred four things with filed tickets. This batch delivers all four, plus two gaps discovered while doing so that were closed here rather than filed — both were the same defect class the batch exists to fix, and deferring them would have been filing a ticket against work already open on the bench.

Two of the four tickets turned out to be partly wrong about their own subject, and finding that out was most of the value. V26-1315's stated diagnosis was inverted and its acceptance criteria were mutually unsatisfiable; the real defect was larger than described and reached the computed order total. V26-1318's suggested reproduction lever did not work, and the agent diagnosed the actual mechanism instead, producing a sensor that reproduces in 71 seconds what coverage instrumentation never reproduced in 15 minutes.

One new defect surfaced and was deliberately not folded in: entire-order discounts applied per line item in fulfillment emails, filed as V26-1319 at High.

What was deferred, and why it came back

V26-1315 — discounts rendering at 100x. Found while delivering a behavior-preserving refactor, so it was characterized as-is rather than fixed: correcting it inside that refactor would have hidden a behavior change inside a move.

V26-1316 — six Convex id fields left as any. Typing them was attempted during the epic and reverted, because branded id types break plain-string test fixtures across unrelated files.

V26-1317 — advisory migration signals that lied. The gate itself was sound, but the field an operator polls to see outstanding work could report zero while rows remained. Expressing "never measured" needed a schema change.

V26-1318 — a CI-only flake. A test failed remotely and passed on re-run of the identical commit. The deeper problem was that local validation could not reproduce it at all.

The two gaps. The browser-boundary sensor scanned src/ only, never shared/ — the directory the epic had just moved ten browser-safe modules into. And getProductDiscountValue documented its value as GHS while operating on pesewas.

The thread running through all six

Every item here is a sensor that could not fail — an assertion, a scan, or a status field that reported success while the thing it described was untrue.

  • A test name promising an assertion it did not make.
  • A fixture whose line items were 100x smaller than their own order, pinning fictional behavior.
  • A boundary scan that never looked at the directory the code moved to.
  • A regex rule that a path alias walked straight through.
  • A remaining: 0 that meant "never measured".
  • A comment asserting units the code did not use.

A passing sensor and a sensor that cannot fail produce identical output. The only way to tell them apart is to introduce the defect and watch. That discipline — re-break the code, confirm red, restore — was required of every workstream here and is now recorded as a durable note.

Before and after

Order discounts (V26-1315)

Before: a local getDiscountValue carried an isInCents multiplier that diverged from the shared order-math authority. After: it delegates to that authority, with one toDisplayAmount at the display boundary. The stored value was always pesewas — the label rendered it as cedis while the amount line multiplied and divided by 100.

Migration run record (V26-1317)

Before: remaining was a required number, so an applying first-touch wrote 0 — indistinguishable from a drained table. After: it is optional and paired with remainingMeasuredAt; absent means never measured, and the status query reports null. A sticky cutoffChangedAt prevents a chain run at the wrong cutoff from banking a completion.

Browser boundary (gap)

Before: scanned src/ only, matched only from "…" imports, and missed the @cvx/* alias entirely. After: scans src/ and shared/ — 1,090 files — normalizes aliases before applying the allowlist, catches dynamic and side-effect imports, and asserts each scan root is non-empty.

Timing parity (V26-1318)

Before: no local way to reproduce a CI-only race. After: test:timing-parity scales timers by a configurable factor, reproducing the cause in 71 seconds; registered in the validation map.

What changed — and what did not

Changed

  • Operator order summary, order detail and orders-list totals now render and compute discounts in pesewas consistently. Percentage discounts were also affected on realistic data, and the clamp capping a fixed-amount discount at the eligible subtotal stopped holding — not because it compared mixed units, but because the ×100 scaling ran on the clamp's result: the comparison was like-unit and bound correctly, then the cap was destroyed downstream.
  • The POS migration run record distinguishes unmeasured from zero, and a wrong-cutoff run is now visible in the status query rather than presenting as a clean board. skipped is cumulative, matching migrated.
  • Two genuinely racy POS tests fixed; a third-party-visible sensor added to find more.
  • The browser boundary covers shared/, alias forms, and dynamic imports.

Deliberately unchanged

  • The completion gate. complete and cumulative migrated were verified sound across 24 executed sequences in the epic; V26-1317 was required to leave them untouched, and the existing guard tests pass byte-identical.
  • Runtime retry and backoff behavior of the POS local sync runtime. V26-1318 is a test-determinism and parity ticket; the injected regression used to falsify the fix was reverted.
  • Discount storage and the minor-unit domain model. Only presentation and the shared read path changed.
  • Entire-order-vs-line-item discount scope in fulfillment emails. Real, customer-visible, and filed as V26-1319 — a modelling question on a different axis, pinned as observed behavior with a comment so the test is not read as an endorsement.
  • The athena-contracts type-only Convex seam. An instrumented build proved convexModel.ts is not in the bundle at all; extending a runtime-boundary scan across a package line to flag an erased edge would be a design decision, not a fix.

Guidance

  • A ticket's diagnosis is a hypothesis. Two of four here were wrong about their own subject. Verify the premise against the code before implementing to it — and when acceptance criteria conflict, say which you chose and why rather than silently satisfying one.
  • Check that a characterization fixture is internally coherent before trusting what it pins. Line items that cannot sum to their own order describe a system that does not exist.
  • Reproduce the cause, not the correlate. Coverage instrumentation was where the flake appeared, so it looked like the lever; it never reproduced locally. Timer lag did, in a fiftieth of the time.
  • Let the sensor discriminate. Grep found far more candidate racy sites than could be triaged by eye — and no reproducible count, since the total swings by hundreds with how the pattern is defined. The parity sensor found the 2 that were real. Do not triage by eye what a tool can decide, and do not report a number a rescan will not reproduce.
  • An allowlist is a deferred decision. Resolving a new boundary violation by adding an exception undoes the ticket that removed the exceptions.
  • Close a gap when it is the same defect class you already have open. Filing a ticket against work sitting on the bench is deferral with extra steps — but a genuinely different axis, like V26-1319, still deserves its own characterization pass.

Comprehension quiz

Ten questions on what actually happened here.

  1. What was wrong with V26-1315's stated diagnosis?

    1. The discount was not rendering incorrectly at all.
    2. It claimed the stored value was cedis; it is actually minor units, so the direction of the error was inverted.
    3. The defect was in the storefront, not the operator surface.
    4. Percentage discounts were the only ones affected.

    Promo fixed amounts are parsed to minor units and copied onto the order unchanged. The label rendered pesewas as cedis. Same symptom, opposite cause.

  2. Why could V26-1315's acceptance criteria 1 and 4 not both be satisfied?

    1. They referred to different components.
    2. AC1 presumes the stored value is cedis while AC4's cross-surface agreement requires pesewas, which five other surfaces already use.
    3. AC4 was added after the work started.
    4. AC1 required a schema change that AC4 forbade.

    Honouring AC1 literally would have broken emails, storefront order detail and review, and the checkout panel. AC4 was chosen; AC1 holds in substance.

  3. How did the characterization fixture hide a second defect?

    1. It omitted percentage discounts entirely.
    2. It used a mocked formatter.
    3. Its line items were 100x smaller than the order total, so the multiplier's effect on percentage discounts and on the clamped fixed-amount discount cancelled out invisibly.
    4. It ran only in CI.

    With a coherent fixture, a 10% discount on a GH₵1,500 order rendered GH₵15,000, and a fixed-amount discount clamped to the eligible subtotal was then scaled past it — Math.min(200000, 150000) bound correctly at 150,000 pesewas and still rendered GH₵15,000,000.

  4. Why did coverage instrumentation fail as a reproduction lever for the flake?

    1. It could not be run locally.
    2. It was correlated with the failure but not its cause; the cause is timer callbacks landing late relative to microtask work.
    3. It disabled the test entirely.
    4. It changed the retry threshold.

    Coverage stayed green 8/8 locally and under 24 competing busy-loop processes. Scaling timers 10x reproduced the verbatim CI failure 5/5.

  5. What makes await waitFor(positive) followed by a negative assertion unsound?

    1. waitFor does not support async callbacks.
    2. The negative assertion runs before the render completes.
    3. waitFor resolves on the first occurrence, so work the awaited chain will still perform can trigger the negative-asserted call afterwards.
    4. Vitest evaluates assertions out of order.

    Here the first ingest call resolved the wait roughly four drains before the retry chain hit its dead-letter threshold.

  6. Why was the browser-boundary sensor's green result misleading before this batch?

    1. It ran only on pull requests.
    2. It resolved its scan root from its own file location, so it walked src/ only and never shared/, where the epic had just moved ten browser-safe modules.
    3. It excluded TypeScript files.
    4. Its allowlist matched everything.

    The gap was structural, not a rule error — the sensor could not fail on a directory it never opened.

  7. Which import form was a genuine bypass of the old boundary rule?

    1. Relative imports two levels up.
    2. The @cvx/* path alias, which resolves to ./convex/* but matched neither ~/convex/ nor a relative path.
    3. Named imports with aliasing.
    4. Re-exports from an index file.

    It is a real alias in both the Vite and TypeScript configs. Specifiers are now normalized before the allowlist is applied.

  8. What does an absent remaining now mean on the migration run record?

    1. The table is drained.
    2. The record is corrupt.
    3. Never measured, or the measurement was invalidated — the status query reports it as null rather than zero.
    4. The migration has not started.

    Only a dry run can measure work left. A number is now a claim someone earned, rather than a default that reads as "nothing left".

  9. Why did the branded-id test helper have to pass its value through verbatim?

    1. To keep the helper generic across tables.
    2. Because Convex validates id formats at runtime in tests.
    3. Several tests assert on the exact fixture strings, so prefixing the table name would have silently broken them.
    4. To avoid a circular import.

    The branding comes from the type parameter alone. Passing the table name in constrains the type without changing any observable value.

  10. Why was the fulfillment-email discount defect filed rather than fixed here?

    1. It is not customer-visible.
    2. It was already covered by an existing ticket.
    3. It is an order-level-versus-line-level modelling question on a different axis from the units work, needing its own characterization pass and a decision about how discount scope is represented.
    4. The affected code is owned by another team.

    It was pinned as observed behavior with an explicit comment so the existing test is not mistaken for an endorsement, and filed at High as V26-1319.

Subagent evidence

Four ticket subagents, one per ticket, isolated worktrees
Each held to its ticket's posture — test-first for the discount fix, sensor-only for the id typing, characterization-first for the migration signals and the flake. Each was required to falsify its own fix and report the red output. Two reported that their ticket's premise or suggested approach was wrong, which is the single most valuable thing they produced.
Two gap-closing subagents, dispatched mid-delivery
One extended the boundary sensor and measured browser reachability with an instrumented Vite build rather than reasoning about it; it found the @cvx bypass that nobody had asked it to look for. The other built the caller inventory for getProductDiscountValue, concluded the comment was stale rather than the code wrong, and surfaced the separate line-item scope defect.
Process note
The epic's review round was run inside the active delivery worktree and a reviewer's cleanup destroyed staged work. This batch dispatched every subagent into its own Claude-managed worktree from the start, and the integration worktree was created with the repo's own worktree-manager.sh script rather than raw git worktree add.
