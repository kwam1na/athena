# Athena Webapp Architecture

The app is a TanStack Router browser client in [src/main.tsx](../../src/main.tsx). The generated route tree in [src/routeTree.gen.ts](../../src/routeTree.gen.ts) fans into public/login routes plus the authenticated shell rooted at [src/routes/\_authed.tsx](../../src/routes/_authed.tsx). Most user-facing work starts by figuring out whether the change belongs in route composition, a feature component under `src/components`, or a data hook under `src/hooks`.

Backend and integration boundaries sit in Convex. The top-level HTTP entrypoint [convex/http.ts](../../convex/http.ts) mounts Hono routes for owner/admin core flows, storefront commerce, guest checkout, rewards, and payment webhooks. Core route composition is grouped in [convex/http/domains/core/routes/index.ts](../../convex/http/domains/core/routes/index.ts), customer-channel HTTP surfaces are grouped in [convex/http/domains/customerChannel/routes/index.ts](../../convex/http/domains/customerChannel/routes/index.ts), and payment collection/webhook routes live under [convex/http/domains/moneyMovement/routes/index.ts](../../convex/http/domains/moneyMovement/routes/index.ts). Shared persistence shape lives in [convex/schema.ts](../../convex/schema.ts).

The operation admission rail is the backend ingress boundary, and it now covers all of it. Every public Convex `mutation`, `query`, and `action` and every Hono route declares an operation definition and runs through one canonical wrapper per ingress kind — `admitPublicMutation`, `admitPublicQuery`, `admitPublicAction`, `admitHttpRoute`, `admitHttpRead` — all imported from the composition root [convex/platform/operationAdmission.ts](../../convex/platform/operationAdmission.ts). Actor, scope, capability or read intent, readiness, effects, and demo-fixture target guards are declared on the definition instead of being asserted ad hoc inside handlers, and identity comes from `ctx.operationAdmission` rather than from arguments. There is no exemption list and no migration inventory: `bun scripts/convex-operation-admission-check.ts` must exit 0 with zero findings, and the only non-admitted ingress is the Convex Auth registrar exports, which mint the principals the rail's adapters later resolve. Read [convex/operationAdmission/README.md](../../convex/operationAdmission/README.md) before adding or changing a public Convex function or HTTP route — adding one means adding a definition under [convex/operationAdmission/domains](../../convex/operationAdmission/domains), not just an export.

The agent harness is the second backend authority boundary, and it is deliberately separate from the ingress rail above. An agent run never becomes an actor of that rail: it holds a derived grant pinned at run start, and every capability read re-derives the initiating operator's current authority through one registered authority port, intersects it with the pinned grant (shrink only), and re-checks a live shrink-only enablement overlay. The kernel is [convex/agentHarness](../../convex/agentHarness) — durable run/attempt/call state, the generated capability registry, delegated admission, the bounded QuickJS program executor, evidence and citations, the turn host, and the deployment switch — and it may not import a product domain. Domains publish semantic capabilities next to their read code under `convex/<domain>/agentCapabilities/`, and profiles select packages into a surface. The model sees five fixed tools and one grant-projected `athena.<package>.<resource>.get|list` facade; there is no mutation reach and no command verb. Convex Agent is the sole runtime, reached only through the adapter contract in [shared/agentHarness/agentRuntime.ts](../../shared/agentHarness/agentRuntime.ts), and only [convex/agentHarness/agentRuntime](../../convex/agentHarness/agentRuntime) may import `@convex-dev/agent`, `ai`, or `@ai-sdk/*` — the root [convex/convex.config.ts](../../convex/convex.config.ts) mounts the component and imports the constants-only registration shim. Convex Agent owns thread and message mechanics for a turn; Athena owns every business fact — run, attempts, calls, budgets, grants, evidence, citations, artifacts — and no business record is ever reconstructed from component state, whose contents are an allowlist verified by test. Profiles are default off behind one durable switch (`bun run agent-harness:switch`), which is also the rollback; a behavioural read-port change moves the compatibility digest and requires the pre-deploy fence (`bun run agent-harness:fence`), one atomic transaction that invalidates old-digest runs rather than draining them. Release is publish, smoke through the direct harness while the switch is off, one broad enable, watch the first turns, disable to roll back — there are no cohorts, canaries, staged profile versions, or deploy-drain gates, and none should be added here. Extending the harness means adding a manifest, a read port, a package, a profile, and a presentation adapter — never kernel code. Read [capability-authoring.md](./capability-authoring.md) before adding a capability, a package, a profile, or a surface, and [agent-harness-runtime.md](./agent-harness-runtime.md) before touching the runtime or sandbox pins.

The harness has a second exposure rule alongside release, and it is named: **"Provisional stream, recallable view."** While a turn runs, the model's narrative reaches the operator live as explicitly provisional text — it is the assistant thinking out loud, a different string from the `narrative` it later hands `completeRun`, and `completeRun`'s committed artifact is still the only released answer. The invariant this replaces the foundation's buffering rule with is: _the narrative never enters Athena's durable record, projected history, a citation, or a prompt, and never survives a terminal cause._ Mechanically, the adapter emits `narrative_delta { draftOrdinal, text }` (text parts only; reasoning, tool, source, and file parts are default-denied), the turn host coalesces them in memory, and one single-flight host-only internal flush in [convex/agentHarness/turns.ts](../../convex/agentHarness/turns.ts) writes them into `agentProvisionalNarrative` — a delete-only table with no state column, `retentionClass: "short_lived"`, indexed by turn binding, expiry, store, and organization, holding at most one row per binding. Its row helpers live in the leaf module [convex/agentHarness/provisionalNarrative.ts](../../convex/agentHarness/provisionalNarrative.ts), which imports only generated server types and carries its own 5-minute TTL literal precisely so all five call sites can reach it without an import cycle. The flush is the single enforcement point: profile policy, live grant reauthorization, binding state, and the turn's stamped egress class against the operator's _current_ grant, with any refusal deleting the row in the same transaction.

That invariant has exactly two granted exceptions, both narrow, and neither of them reaches a projection, a prompt, or a citation. The first is engineer-only: the turn trace (`agentTurnTraceEvent`) records every runtime event of a driven turn — the narrative deltas, each tool call's exact arguments, and the outcome the model received — so an engineer can replay a turn offline while refining the agent, and it is never projected into thread history, a prompt, a citation, or any operator-admitted query, and never read by any admitted public function ([agent-harness-runtime.md](./agent-harness-runtime.md) §5).

The second is the operator's own: the **narrative trail** (`agentTurnNarrativeTrail`), one insert-once row per _committed_ turn holding that turn's finished drafts in order. Its rule is that the trail is released and withdrawn **with the answer**, never apart from it: it is written only at `finalizeTurnWithCtx` for a run that reached `completed` with a committed release, it is stamped with the committed artifact's own egress class, and `getTurnNarrativeTrail` applies the ladder `getTurnAnswer` applies plus the narrative-policy rung — `reauthorizeTurnAccess` (`not_found` until ownership is established), the profile's `narrativePolicy` (`policy_disabled`), suppression, the commit, then the stored class against the viewer's current grant — so there is no state in which an operator can read the drafts but not the answer. Nothing is written for a canceled, failed, or refused turn, and a draft the kernel ever withdrew mid-turn is never handed on. Its row helpers live in the leaf module [convex/agentHarness/narrativeTrail.ts](../../convex/agentHarness/narrativeTrail.ts), which imports only generated server types and carries its own 365-day retention literal; the table is standard-class, capped at `AGENT_TURN_NARRATIVE_TRAIL_MAX_BYTES` (96 KiB per turn, spread across drafts so a runaway draft cannot erase its neighbours and no ordinal is ever dropped), expired by the standard retention sweep, and deleted by store and organization removal through its own scope indexes. Suppression does not delete it — the row stays and the ladder refuses, exactly as the committed artifact does. It is what lets the pane's drafts survive a reload and lets an earlier turn in the thread expand them again; `historyProjection.ts`, the prompt assembler, and `citations.ts` name it nowhere, and a containment test in `historyProjection.test.ts` holds those lists exact.

Deletion is per terminal cause and never inside the commit transaction: the lifecycle clamp deletes for every terminal status except `completed` (cancel, failure, kill switch, fence repair), `suppressReleaseWithCtx` deletes on post-commit revocation from outside its already-suppressed guard, the host's `finalizeTurnWithCtx` deletes at the end of every driven turn (covering both a successful commit and a commit followed by a provider failure), store and organization removal delete through the table's own scope indexes, and the repair sweep's expiry phase deletes rows a dead host left behind and logs its count. The browser reads the draft only through `previewTurnNarrative`, an operation-admitted reactive query that never writes and walks a fail-closed ladder — turn ownership and live authority, epoch fence, profile policy, egress rank against the write-once provider-invocation row, suppression and abandonment, run state, expiry — returning a discriminated union whose only text-bearing arm is `streaming { released, text, truncated, draftOrdinal, updatedAt, expiresAt, ttlMs }`; `not_found` is the bare pre-ownership arm, `withdrawn { reason, released }` carries one of a closed reason set (`compatibility_epoch_fenced`, `policy_disabled`, `egress_beyond_authority`, `suppressed`, `abandoned`, `run_canceled`, `run_failed`), and `disabled`, `awaiting_first_text`, `stalled`, and `superseded` carry `released` and nothing else. `acknowledgeProvisionalView` records a first-write-wins `provisionalViewedAt` and refuses unless a release actually happened. The host derives its own `provisionalState` from that preview and the turn view — `disabled`, `withdrawn`, `superseded`, `committing`, `reset`, `paused_at_limit`, `streaming`, `awaiting_first_text`, `stalled`, `none`, first match wins in that order — as a presentation field separate from the kernel's closed, server-declared `AgentHostState`, which this rule does not widen.

AI, LLM, recommendation, provider, retrieval, and future media-generation work belongs in the Athena intelligence layer documented in [intelligence.md](./intelligence.md). Do not add new durable behavior to the old `convex/llm` seam except as a temporary compatibility wrapper during migration. Athena-owned Convex tables, run/artifact state, context snapshots, provider invocations, review operations, authorization checks, and future apply boundaries remain the source of truth; TanStack AI, model providers, and optional Convex Agent/RAG/Durable Agents components stay adapter or runtime helpers below that contract.

Client/server command error handling now has an explicit shared foundation. Use [shared/commandResult.ts](../../shared/commandResult.ts) for browser-safe `ok` and `user_error` results that both Convex and React code can import without crossing the browser/server boundary. Approval-sensitive commands opt into [shared/approvalPolicy.ts](../../shared/approvalPolicy.ts) and return `approval_required` through the same command result rail rather than burying approval in success payloads. Browser code should normalize command execution through [src/lib/errors/runCommand.ts](../../src/lib/errors/runCommand.ts), surface safe `user_error` copy inline when the action has a durable error region, use toast only as a fallback for toast-only actions through [src/lib/errors/presentCommandToast.ts](../../src/lib/errors/presentCommandToast.ts), route legacy toast-only admin quick actions through [src/lib/errors/presentUnexpectedErrorToast.ts](../../src/lib/errors/presentUnexpectedErrorToast.ts), and let [src/components/auth/DefaultCatchBoundary.tsx](../../src/components/auth/DefaultCatchBoundary.tsx) stay the generic route/render backstop for escaped faults. Raw thrown server text is never acceptable user-facing copy, and [src/routeTree.browser-boundary.test.ts](../../src/routeTree.browser-boundary.test.ts) guards the browser import boundary for shared modules. One consequence of Convex transaction semantics constrains the choice between throwing and returning: a mutation that throws rolls back its own writes, so a rejection that must leave an audit row behind has to be **returned** as a `user_error`, never thrown — throw only when losing the audit is acceptable. The product archive precondition ([convex/inventory/helpers/productArchivePrecondition.ts](../../convex/inventory/helpers/productArchivePrecondition.ts)) is the reference case, and the reusable rule plus the read-model invariant it protects are in [docs/solutions/architecture-patterns/athena-source-transition-operational-work-reachability-2026-08-22.md](../../../../docs/solutions/architecture-patterns/athena-source-transition-operational-work-reachability-2026-08-22.md).

The browser bundle imports exactly one thing from `convex/`: the generated client under [convex/_generated](../../convex/_generated). There is no allowlist of extra Convex modules, and [src/routeTree.browser-boundary.test.ts](../../src/routeTree.browser-boundary.test.ts) fails on any other `~/convex/...` specifier reached from `src`. Code the browser and the server genuinely share belongs in `shared/`, with a thin re-export left behind in `convex/` so server callers keep their existing import path — that is the pattern already used by [shared/textCase.ts](../../shared/textCase.ts) and now also by [shared/currency.ts](../../shared/currency.ts), [shared/formatDate.ts](../../shared/formatDate.ts), [shared/transactionNumber.ts](../../shared/transactionNumber.ts), [shared/orderMath.ts](../../shared/orderMath.ts), [shared/geography](../../shared/geography), [shared/notificationCategories.ts](../../shared/notificationCategories.ts), [shared/notificationDeliveryPolicy.ts](../../shared/notificationDeliveryPolicy.ts), and [shared/storeScheduleTime.ts](../../shared/storeScheduleTime.ts). Shared modules must stay dependency-light: a `shared/` file that reaches back into hand-written `convex/` code — or into the package-root `types.ts`, which resolves Convex schema types — re-crosses the boundary it exists to remove, so declare the structural shape locally instead. `convex/_generated/` is the one exception, exactly as it is for the browser bundle: a type-only import of `Id`/`Doc` from the generated model erases at build, adds no runtime edge, and is how [shared/storeScheduleTime.ts](../../shared/storeScheduleTime.ts) types its id fields. Presentation that only the browser renders is frontend-owned, not shared: the POS and expense receipt email templates live in [src/lib/pos/receipts](../../src/lib/pos/receipts) because nothing on the server sends them.

The command approval policy layer is domain-owned and command-enforced. Domain commands decide whether an action is allowed, denied, unsupported, requires inline manager proof, or requires async approval; shared types only define the browser/server contract. Inline manager approval must mint a short-lived, one-use, action/store/subject/role-bound proof through [convex/operations/staffCredentials.ts](../../convex/operations/staffCredentials.ts) and [convex/operations/approvalProofs.ts](../../convex/operations/approvalProofs.ts), then the protected command must consume that proof before mutation. Do not treat a client-supplied `staffProfileId` as approval. Shared React presentation lives in [src/components/operations/CommandApprovalDialog.tsx](../../src/components/operations/CommandApprovalDialog.tsx). Approval observability goes through [convex/operations/approvalAuditEvents.ts](../../convex/operations/approvalAuditEvents.ts) and [convex/operations/operationalEvents.ts](../../convex/operations/operationalEvents.ts); only domains with an existing trace lifecycle, such as register closeout variance review through [convex/operations/registerSessionTracing.ts](../../convex/operations/registerSessionTracing.ts), should add workflow trace milestones.

POS local-sync inventory authority lives in [convex/pos/application/sync/projectionPolicies.ts](../../convex/pos/application/sync/projectionPolicies.ts). Active provisional imports remain evidence-only, finalized provisional lineage becomes trusted sale demand, and stock precondition failures create `synced_sale_inventory_review` Operations work instead of requiring Cash Controls manager approval. Use the production repair runbook at [docs/operations/pos-sync-finalized-lineage-remediation-2026-07-06.md](../../../../docs/operations/pos-sync-finalized-lineage-remediation-2026-07-06.md) when correcting already-conflicted finalized-lineage sync events.

Manager approval authority must stay separate from the signed-in Athena session. Treat requester fields (`requestedByUserId`, `requestedByStaffProfileId`), reviewer-session fields (`reviewedByUserId`, `reviewedByStaffProfileId`), and decision-authority fields (`decisionApprovalProofId`, `decisionApprovedByStaffProfileId`) as different lanes. Domain records that apply an approved command should persist the proof lane explicitly, such as `voidDecisionApprovalProofId`, `completionApprovalProofId`, or `reopenApprovalProofId`, while keeping legacy compatibility fields only for existing readers. Automation evidence remains its own lane and should not backfill human approval proof fields. The durable pattern note is [Athena Manager Approval Authority Is Decision Evidence](../../../../docs/solutions/architecture/athena-manager-approval-authority-standard-2026-07-01.md).

The Reports foundation is owned by [convex/reports](../../convex/reports), with persistence contracts in [convex/schemas/reports](../../convex/schemas/reports) and browser-safe metric vocabulary in [shared/reportsContract.ts](../../shared/reportsContract.ts). Source commands write typed facts inside their own transaction through [convex/reports/ingest.ts](../../convex/reports/ingest.ts); fact identity is structural — `(storeId, sourceDomain, sourceId, lineId, factKind)` — so a replay is a no-op and a content conflict quarantines rather than overwrites. `occurredAt` is business time, never sync or arrival time. Any physical quantity, availability, movement, SKU Activity, or valuation change remains inline with the owning mutation and must commit or roll back as one operational outcome; `recordFacts` never throws into its caller, degrading instead to a dirty mark so a reporting fault cannot roll back a sale.

The correctness authority is the deterministic day fold in [convex/reports/foldDay.ts](../../convex/reports/foldDay.ts): a pure function from one operating day's facts to that day's totals, which is simultaneously the rebuild, the reconciliation, and the backfill apply step. [convex/reports/sweeper.ts](../../convex/reports/sweeper.ts) drains declarative dirty marks on a cron and replaces day, SKU-day, rollup, and overview documents wholesale, so re-running it is a no-op and at-least-once delivery is sufficient. The open day is patched incrementally as facts land and is labelled `open` — treat that as a preview, not the truth, because the close-time fold replaces every number it wrote. [convex/reports/queries.ts](../../convex/reports/queries.ts) and [convex/reports/access.ts](../../convex/reports/access.ts) own bounded, store-scoped full-admin reads; operational workflows must never read reporting to decide whether their source command succeeded. Day status describes settlement timing — `reconciled` means a close exists and nothing landed after it, not that the numbers agree, so a reconciled day can still carry a close variance. Preserve unknown cost as an explicit state rather than coercing it to zero. [convex/reports/verify.ts](../../convex/reports/verify.ts) recomputes days directly from domain tables through deliberately independent code, and [convex/reports/reseed.ts](../../convex/reports/reseed.ts) rebuilds a store from source — the same path serves bootstrap, backfill, and disaster recovery. Inventory valuation and costing live in [convex/inventoryLedger](../../convex/inventoryLedger), and operating-day/timezone authority in [convex/storeTime](../../convex/storeTime); both are depended on by operational domains and are not reporting code.

Admin/manager outbound communications go through the notifications rail in [convex/notifications](../../convex/notifications), with persistence in [convex/schemas/notifications.ts](../../convex/schemas/notifications.ts). Domain mutations hand notifications to `emitNotificationWithCtx` or `scheduleNotificationWithCtx` and never touch channels, recipients, templates, or transport. Immediate kinds dispatch with `runAfter(0)`; the accepted weekly manager report deliberately schedules its intent for 8 AM on the next store-local day through the same boundary. The code-owned catalog in [convex/notifications/registry.ts](../../convex/notifications/registry.ts) declares each kind's category, dedupe recipe, and render-at-send `prepareEmail`; a `prepareEmail` throw is a transient fault and stays retryable, while a `prepareEmail` null means the subject is genuinely unsendable and suppresses the delivery — the two must not be collapsed. Audience resolves from `notificationSubscription` rows (org × optional store × category × channel), with `ADMIN_EMAILS` as the fallback **only** when the org has zero subscription rows for the category; once rows exist, an empty filtered match (all disabled, or scoped elsewhere) is an intentional empty audience and suppresses the intent instead of falling back — disabling every subscription in a category silences it. Deliveries are individually ledgered with lease tokens, backoff, and provider idempotency keys. Because a dispatch sends its batch serially, the **batch** is bounded (`MAX_DELIVERIES_PER_DISPATCH`) rather than the lease stretched: a lease long enough for a full audience would outlive the platform action limit, so the action would be killed mid-batch with every leased row already holding an attempt, leaving the tail uncontacted. Each pass therefore leases at most one batch, takes a lease sized to it (capped below the action limit), and re-schedules itself for the remainder — and leaves the intent `pending` until the audience is fully materialized, so a lost continuation is recovered by the sweeper's pending-intent phase rather than becoming an invisible partial send. Deliveries are drained by the immediate dispatch plus the "notifications sweep" cron (every 5 minutes in prod, 60 elsewhere), which runs independent per-phase budgets and abandons a pending intent once it has sat unreserved for longer than `INTENT_ABANDON_AFTER_MS` (6h, wall-clock — measured from the later of `emittedAt`/`requeuedAt`, not a pickup count; `sweepAttempts` is now a diagnostic counter only). `requeueAbandonedIntent` in [convex/notifications/sweeper.ts](../../convex/notifications/sweeper.ts) is the operator recovery path — a dashboard-only internalMutation, no internal callers — that resets an intent suppressed with `dispatch_unrecoverable` back to pending, clears `suppressedReason`, zeroes `sweepAttempts`, and stamps `requeuedAt` to restart the abandonment clock while preserving `emittedAt` as the audit record of when the domain moment happened. The environment gate lives in [convex/notifications/transport.ts](../../convex/notifications/transport.ts): non-prod redirects to `NOTIFICATIONS_DEV_RECIPIENT` when set, or otherwise records the delivery as `suppressed` (never a false `sent`) without calling the provider, so every environment exercises the full pipeline. A delivery that terminally fails records a `notification_delivery_failed` operational event, as does every intent-level suppression (`no_recipients`, `no_deliverable_channel`, `unknown_kind`, and any `markIntentSuppressed` reason including `payload_unavailable`); a delivery that merely completes as `suppressed` deliberately does not get its own event. `subscription_cap_exceeded` also records an event but is **not** a suppression — resolution truncates to the cap and the notification is still delivered to the resolved audience. A closeout whose variance review cannot be resolved because a single status overflowed its lookup page records `register_closeout_notification_skipped` and is skipped rather than risking a false all-clear. Sweeper-originated failure events are recorded through a scheduled mutation rather than inline, because recording scans the subject's full event history and a sweep's worth of stale leases plus abandonments in one transaction could exceed the read limit and roll back the sweep itself. Three cutover-guard lanes exist for one release to stop batches replayed across the deploy boundary from re-alerting for moments the pre-rail path already reported: `convex/pos/public/sync.ts` reads the legacy `varianceNotificationScheduledAt` and `closeoutNotificationLocalEventId` markers, and the EOD action-required path in `dailyOperationsAutomation.ts` consults the legacy `automationNotificationDelivery` ledger via `wasActionRequiredNotifiedBeforeRail` before emitting; EOD applied/prepared sends are deliberately left unguarded (the pre-rail path never ledgered those). All three are deletable once no unnotified pre-deploy moment remains — the EOD lane can only ever match pre-cutover store-days since `operatingDate` strings are never reused. Adding a new communication = one registry entry + one template in [convex/emails](../../convex/emails); do not add new per-call-site email sends.
